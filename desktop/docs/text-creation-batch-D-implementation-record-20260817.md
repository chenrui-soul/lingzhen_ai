## 本批次实现

### 资料研究动作

- 资料查找：生成检索词、建议来源、交叉核验问题和查找步骤；
- 资料摘要：依据明确摘录整理摘要并标注来源；
- 要点提取：提取事实、观点、数据、时间和待核验事项；
- 对比分析：比较至少两个不同素材的一致点、差异、冲突和证据缺口；
- 来源清单：整理来源位置、摘录范围、可支持观点、局限和后续核验建议。

当前模型网关没有联网检索契约。“资料查找”不会伪装成已经联网取得结果，只输出检索计划和核验框架。

### 来源和上下文安全

- 只显示当前项目正式文本素材；
- 长文打开后必须由用户明确选择片段，未选择时拒绝加入；
- 提供“明确选择全部可读内容”，但仍受单段上限控制；
- 单个摘录上限 4000 字；
- 单次最多 8 个来源；
- 总上下文上限 9000 字；
- 对比分析要求至少两个不同 `assetId`；
- 每个来源保留 `assetId`、项目、来源名称、来源位置、摘录起止范围、摘录字符数、指纹和选择时间；
- 提交预览显示 `[S1]` 来源编号、范围、上下文大小、实际模型和非敏感参数；
- 原始长文素材文件不会通过 `assetIds` 整篇传入模型任务。

### 文献摘录和素材中心

- 用户可以从当前项目素材中选择摘录；
- 用户也可以手动录入来源名称、链接或文献位置和明确摘录；
- 手动文献先通过共享 `assets.createText()` 契约保存为素材中心正式文本素材，再加入研究上下文；
- 不建立第二套素材数据库，不直接写素材目录；
- 研究结果可以通过同一共享契约保存为 `text-research-analysis` 正式素材；
- 保存后的 `assetId` 写回研究结果，按钮锁定，避免重复保存。

### 统一任务与结果恢复

- 研究任务进入统一 `generation.create()`；
- 使用 `creationType: "text"`、`creationSource: "text-workspace-research"` 和 `executionChannel: "model-gateway"`；
- 任务与原项目、原 conversation、原文档、来源摘录和 `clientRequestId` 通过租户隔离执行信封绑定；
- 与批次 C 相同，任务不携带会触发主进程自动覆盖正文的顶层 `conversationId`；
- 研究任务不携带原始 `assetIds`，防止模型网关再次读取整篇来源；
- 结果恢复只读取 `workbench.bootstrap()`、任务结果和 `assets.readText()`，不会重新调用生成；
- `taskId/resultId/clientRequestId` 用于研究结果幂等合并；
- 页面刷新后恢复已有研究结果、摘录草稿和保存状态。

### 结果处理

- 保留为候选：通过批次 C 的文本内部候选接口进入原文档 AI 候选区；
- 创建候选版本：保存为候选分支版本，不覆盖正文；
- 保存到素材中心：生成正式文本素材并保留来源清单；
- 放弃：只隐藏研究结果，不删除统一任务或结果素材；
- 所有路径都不会自动修改正文。
