# 人工核对状态操作修复记录

修复支线：`human-attention-actions`  
建立日期：2026-08-16  
基线快照：`backups/human-attention-actions-20260816/baseline/manifest.json`

## 问题

截图中的“等待人工核对”对应任务状态 `submission_unknown`，表示系统无法确认豆包是否已经收到提交。该状态不能自动重提，也不能自动释放账号，但旧界面只有状态提示，没有明确人工决策入口，导致任务看起来永久卡住。

## 修复后的行为

### 1. 打开原账号现场

从任务坞或任务详情打开原账号 BrowserWindow，继续检查原 conversation。不会创建新窗口分区，也不会新建任务。

### 2. 已确认提交，继续监控

调用原任务的监控入口，继续观察原账号和原 conversation。不会重新发送提示词，不会创建子任务，不会释放账号锁。

### 3. 确认未提交，结束保护

要求用户先在原账号和原 conversation 中完成核对，再二次确认。确认后：

- 原任务标记为人工核对结束的失败记录；
- `safeToRetry=true`、`notSentVerified=true`；
- 记录人工核对时间、账号、conversation 和结论；
- 释放账号锁；
- 不自动创建或提交重试任务；
- 用户可以随后显式点击安全重试，创建新的子任务。

### 4. 没有任何按钮操作时

任务继续保持 `submission_unknown`，账号继续锁定，后台继续做低频原会话审计。系统不会自动停止、自动释放或自动重提。任务坞持续显示“需处理”，直到用户做出明确选择。

## 普通人工验证和登录

`awaiting_verification`、`awaiting_login` 同样提供“打开原账号现场”和“完成后继续”按钮。继续动作沿用原任务和原 conversation，不会重新提交。

## 为取消任务中心做的准备

这三类操作已放入全局任务坞，并保留在兼容任务详情页。后续隐藏任务中心导航后，人工处理仍可在任务坞完成，不依赖任务中心页面。

## 测试结果

- 人工核对动作专项测试：10/10；
- 任务中心回归：20/20；
- 多任务任务坞回归：27/27；
- 豆包失败结果回归：18/18；
- 主进程、预加载和渲染脚本语法检查通过。

真实 Electron 窗口、原账号现场和 Playwright UI 交互仍需在可启动的预览环境中进行最后人工验收。
