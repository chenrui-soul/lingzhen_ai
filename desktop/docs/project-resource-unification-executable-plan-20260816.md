# 项目管理与素材中心合并可执行方案

方案日期：2026-08-16（Asia/Shanghai）  
适用基线：灵帧AI桌面客户端 V0.12.2 内测 HTTP 版  
建议支线标识：`project-resource-unification`  
目标名称：`项目资源库`（界面名称可在实施前改为“项目与素材”）

## 一、执行结论

可以把“项目管理”和“素材中心”合并为一个界面入口，并且不需要给项目增加账号锁、任务锁或并发互斥锁。

但项目不能只作为一个可以随意改名、移动和删除的普通磁盘文件夹处理。后台必须继续保留稳定的项目实体和 `projectId`，因为当前任务、文本会话、无限画布、素材和生成结果都依赖它做归属校验和跨项目隔离。

最终形态建议为：

```text
项目资源库
  ├─ 左侧：项目/文件夹树、归档、回收站
  ├─ 中间：当前项目素材、全部素材、豆包视频、搜索与批量操作
  └─ 右侧：素材详情、生成来源、引用关系、视频 URL 与安全操作
          │
          ├─ 项目在用户界面上表现为文件夹
          └─ 后台继续使用稳定 projectId 作为归属边界
```

本次合并只收敛入口和资源操作，不修改豆包执行链路、任务调度器、模型网关、文本创作、无限画布执行逻辑和任务坞。

## 二、当前真实基线

### 2.1 已有能力

当前实现已经具备以下基础，不需要重新建设：

1. `project-materials.js` 同时维护项目管理和素材中心两套页面；
2. 项目、素材、文本会话和任务都由 `WorkbenchDataBridge` 持久化；
3. 项目删除已经检查素材、文本会话和任务记录；
4. `assets.copy()` / `copyAssets()` 已支持跨项目复制，并为副本生成新 `assetId`；
5. 文本创作会拒绝引用其他项目的素材；
6. 无限画布按租户和项目分别保存，并校验任务项目与画布项目一致后才允许结果回填；
7. 豆包生成结果已经保持 `task.resultAssetId`、`task.resultVid` 与本地素材绑定；
8. 素材中心已支持豆包视频单条复制、逐条选择、当前筛选全选和批量复制；
9. 任务中心已支持单条视频地址复制、批量复制、去重和签名地址时效提示；
10. 项目切换通过 `currentProjectId` 控制当前工作空间，不需要并发锁。

### 2.2 当前主要风险

当前 `updateAsset(assetId, {projectId})` 会把素材文件移动到另一个项目，但继续沿用原 `assetId`。

这会产生以下风险：

- 已完成任务仍指向这个 `assetId`，但任务项目与素材项目变得不一致；
- 文本会话仍保存原 `assetId`，但重新加载时可能被跨项目校验拒绝；
- 无限画布节点仍保存原 `assetId`，但素材已经离开原画布项目；
- 豆包视频 URL、任务、素材和项目的一对一归属可能被破坏；
- 结果恢复时可能被正确的跨项目保护拦截，导致用户误以为结果丢失。

因此，合并后的默认跨项目操作必须是“复制到项目”，生成新 `assetId`；不能继续把被引用素材直接改归属。

### 2.3 本方案制定时的基线测试

| 测试 | 结果 |
|---|---:|
| 项目与素材 | 27/27 |
| 多任务任务坞 | 27/27 |
| 任务中心 | 20/20 |
| 文本工作区 | 21/21 |

## 三、不可修改的模块边界

本支线默认禁止修改：

- `src/main/generation-orchestrator.cjs`
- `src/main/embedded-browser-manager.cjs`
- 豆包浏览器控制、账号队列和账号 Profile
- 模型网关执行与结果恢复
- `src/renderer/task-center.js`
- `src/renderer/generation-ui.js`
- `src/renderer/text-workspace*.js`
- `src/renderer/infinite-canvas*.js`
- `src/renderer/canvas-*.js`
- 既有任务状态、失败分类、额度锁和人工处理 IPC

必须保持：

1. 豆包同账号串行、不同账号并行；
2. 模型网关不占豆包账号锁；
3. `submission_unknown` 不自动重提、不自动释放账号；
4. 人工登录和验证码继续使用原账号窗口、原 conversation；
5. 结果恢复只下载或恢复，不重新生成；
6. 任务、账号、conversation、结果 URL、本地素材和项目归属保持一对一；
7. Asia/Shanghai 额度锁和重置时间不变；
8. 任务坞跨模块常驻；
9. 文本创作和无限画布仍只使用本项目素材；
10. 切换当前项目不能改变已经创建或正在运行的任务归属。

## 四、项目是否需要“锁”

不建立项目锁。

项目不是执行资源，不参与豆包账号排队，也不应阻止不同项目同时运行任务。需要保留的是操作约束，而不是并发锁：

| 操作 | 规则 |
|---|---|
| 新建、重命名、修改说明 | 直接允许 |
| 切换当前项目 | 直接允许，不影响运行中任务 |
| 项目归档 | 项目变为只读，不接受新素材和新任务 |
| 项目恢复 | 恢复为可写工作空间 |
| 删除项目 | 进入回收站；存在素材、文本、任务或画布时阻止 |
| 运行中任务 | 创建后冻结 `task.projectId` |
| 生成结果 | 始终回填到 `task.projectId`，不能使用界面当前项目覆盖 |
| 素材跨项目 | 默认复制并生成新 `assetId` |
| 被引用素材 | 禁止直接改项目归属；删除前显示引用关系并阻止误删 |

因此用户体验上项目可以像文件夹，但后台归属不能像普通文件夹那样被任意重写。

## 五、合并后的界面方案

### 5.1 单一导航入口

左侧导航将：

- “素材中心”改名为“项目资源库”；
- 隐藏独立“项目管理”入口；
- 保留旧 `projects` 和 `materials` 内部路由作为兼容入口；
- 使用功能开关恢复旧双入口，便于回滚。

第一批实现时不删除旧页面函数和旧路由。

### 5.2 页面布局

#### 左侧项目区

- 当前项目；
- 全部项目；
- 进行中；
- 已归档；
- 回收站；
- 新建项目；
- 项目重命名、说明、归档、恢复和删除；
- 每个项目显示素材数、文本数、任务数和最后更新时间。

#### 中间资源区

- 当前项目素材；
- 全部项目素材；
- 豆包视频；
- 图片、视频、音频、文本分类；
- 使用中、已归档、回收站；
- 搜索、标签和项目筛选；
- 网格/列表切换；
- 上传、预览、打开文件位置、引用、复制到项目、归档和删除。

#### 右侧详情区

- 素材名称、类型、大小、标签、说明；
- 所属项目；
- 生成来源和生成时间；
- 关联任务、账号、conversation；
- 被文本会话或画布节点引用的数量；
- 本地文件状态；
- 豆包视频 URL、复制按钮和签名地址时效提示；
- “复制到其他项目”，不提供无保护的“直接移动”。

### 5.3 当前项目切换

标题栏“当前项目”继续保留。项目资源库左侧点击项目后：

1. 调用现有 `projects.setCurrent(projectId)`；
2. 只更新后续新建内容的默认归属；
3. 不修改任何已存在任务、会话、画布和素材的 `projectId`；
4. 不关闭豆包窗口；
5. 不暂停或重排运行任务；
6. 不改变任务坞当前显示的任务。

## 六、素材跨项目的安全规则

### 6.1 默认动作改为复制

“复制到其他项目”继续使用现有 `assets.copy()`：

```text
原素材 asset-A / project-A
        │
        └─ 复制到 project-B
                 └─ 新素材 asset-B
```

副本必须保留：

- `sourceAssetId`；
- `sourceProjectId`；
- 原始名称、类型、标签和说明；
- 独立物理文件；
- 新的 `assetId`；
- 新项目归属。

原任务、文本和画布继续引用 `asset-A`，不会被副本影响。

### 6.2 禁止无保护改归属

支线中将逐步停止 renderer 使用 `assets.update(id, {projectId})`。

数据层最终规则建议为：当 `projectId` 与素材原项目不同时直接拒绝，并提示使用 `assets.copy()`。这样即使将来其他界面误调用，也不会破坏稳定绑定。

该规则必须在独立批次实施并更新专项测试，不能和第一批界面改造混在一起。

### 6.3 删除与归档

- 删除仍为软删除，可恢复；
- 归档不会改变 `assetId` 和 `projectId`；
- 被运行任务、结果任务、文本会话或画布节点引用的素材默认禁止删除；
- 对画布引用的检查由项目资源库只读扫描当前租户的 `lingframe.infiniteCanvas.v2.*` 存储完成，不修改无限画布模块；
- 已完成豆包结果的本地素材不能因为远端 URL 仍可用就直接删除；
- 签名 URL 可能过期，本地素材才是长期结果。

## 七、豆包视频选择与批量复制保护

该能力已经存在，合并时只能迁移展示位置，不能删除或降级。

### 7.1 有效豆包视频判定

只有同时满足以下条件的素材才显示豆包链接操作：

1. 素材类型为 `video`；
2. 任务 `executionChannel === "doubao"`；
3. 任务状态为 `completed`；
4. `task.resultAssetId === asset.id`；
5. `task.projectId === asset.projectId`；
6. `task.resultVid` 非空；
7. 素材未删除；
8. 当前租户可见。

### 7.2 必须保留的操作

- 单条复制豆包视频 URL；
- 单条选择/取消选择；
- 全选当前筛选结果中的豆包视频；
- 取消当前筛选全选；
- 批量复制已选链接；
- 一行一个 URL；
- 自动去重；
- 显示选中数量；
- 数据刷新后清理已经失效的选择；
- 提示签名 URL 可能有时效；
- 可直接打开本地素材；
- 复制动作只读，不修改任务、素材或账号状态。

### 7.3 建议增强

- 增加“全选当前项目豆包视频”，与“全选当前筛选结果”区分；
- 批量复制前显示有效、重复、缺失 URL 的数量；
- 复制失败时使用 renderer 内的兼容复制降级，不新增主进程权限；
- 保持完成时间或素材列表顺序，避免批量复制顺序随机变化；
- 对过长 URL 完整复制，界面只做省略显示；
- 不把 `resultVid` 当作本地文件替代品。

## 九、分批实施顺序

### 批次 0：冻结基线

1. 创建支线目录和基线快照；
2. 记录所有白名单文件 SHA-256；

6. 任一基线失败则先停止，不进入开发。

### 批次 A：建立项目资源库壳层

1. 新增 `resources` 或等价内部页面标识；
2. 复用现有项目和素材状态，不创建第二份数据；
3. 左侧渲染项目列表，中间渲染素材，右侧渲染详情；

6. 不改 `WorkbenchDataBridge`、IPC 和任何生成链路。

### 批次 B：项目操作收敛

1. 把新建、编辑、归档、恢复和删除项目放入左侧项目区；
2. 项目卡片显示素材、文本和任务数量；
3. 项目归档后资源区只读；
4. 切换项目只更新 `currentProjectId`；
5. 在运行任务期间切换项目，验证结果仍回到原任务项目。

验收：项目无并发锁，不影响豆包或模型网关并行；任务归属不漂移。

### 批次 C：素材安全操作

1. 普通编辑只修改名称、标签、说明和归档状态；
2. 项目选择改为“复制到项目”；
3. 使用现有 `assets.copy()` 生成新 `assetId`；
4. 增加素材引用关系只读统计；
5. 被引用素材阻止误删；
6. 数据层拒绝直接跨项目重写 `assetId` 归属；
7. 旧素材、原任务、原文本和原画布保持不变。

验收：复制前后的两个素材可独立使用，原引用不改变。

### 批次 D：豆包视频批量能力迁移

1. 将现有单条链接和选择控件迁移到项目资源库；
2. 增加“豆包视频”快捷筛选；
3. 保留当前筛选全选和批量复制；
4. 增加项目一致、完成状态和结果素材一致校验；
5. 验证一行一个、自动去重和完整长 URL；
6. 增加签名 URL 时效提示和本地素材入口。

验收：新旧入口复制结果一致，复制不触发生成、恢复或账号操作。

### 批次 E：隐藏旧导航

1. 新资源库连续通过静态和运行时测试后，默认隐藏独立“项目管理”导航；
2. 保留旧路由和旧渲染函数；
3. 功能开关可立即恢复双入口；
4. 不同时取消任务中心页面；
5. 不删除历史项目和素材数据。

验收：隐藏导航后所有原操作均能在项目资源库完成。

### 批次 F：隔离预览和主线合并

1. 使用独立 `userData` 启动；
2. 完成静态、Node、Electron/CDP 和人工冒烟；
3. 只按白名单复制通过测试的文件进入共享工作区；
4. 合并后再次执行同一测试矩阵；
5. 生成合并后快照；
6. 保留旧预览和功能开关；
7. 任一门禁失败则不合并。
