# 文本创作独立优化支线

支线标识：`text-creation-optimization`  
建立日期：2026-08-16  
基线快照：`backups/text-creation-optimization-20260816/baseline/manifest.json`

## 一、支线目标

在不改变豆包、无限画布、任务坞、任务中心后台、模型网关和既有调度器行为的前提下，优化文本创作工作台，使其覆盖：

- 故事和小说；
- 剧本和分集剧本；
- 分镜脚本；
- 提示词和提示词模板；
- 广告语、广告文案和短视频文案；
- 人物设定和世界观设定；
- 自动保存、历史版本、恢复、素材引用、导出和AI结果回传。

文本创作是独立来源模块，但生成任务仍必须进入统一 `generation.create()`，结果按原项目、原会话、原文档和原版本上下文回填。

## 二、当前基线

当前已有文本创作能力：

- 多创作会话；
- 小说、故事、广告文案、短视频文案、剧本、分镜、提示词、人物设定、世界观九类文本类型；
- 自动保存；
- 版本快照、查看、恢复和删除；
- 会话归档、回收站和恢复；
- 当前项目素材引用与跨项目拒绝；
- 文本预览和 TXT 导出；
- 文本工作区响应式基线。

当前仍有明显优化空间：

1. 文本类型主要是下拉分类，还没有对应的结构化模板；
2. “生成内容”入口尚未形成完整的文本结果回传链路；
3. 长篇创作缺少章节、场景、人物和世界观上下文管理；
4. 缺少选中文字操作、候选结果、差异对比和分支版本；
5. 剧本和分镜仍以普通文本为主，缺少结构化字段；
6. 缺少文本连续性、人物一致性和广告合规检查。

## 四、设计方向

### 1. 一个工作台，多种创作模式

故事、小说、剧本、分镜、提示词和广告文案使用同一文本工作台，通过模式切换模板、字段、AI动作和导出格式，不拆成多个互相孤立的页面。

### 2. 三栏工作区

- 左侧：项目、会话、文档、章节/场景目录和版本；
- 中间：正文或结构化编辑器；
- 右侧：AI助手、人物/世界观、素材引用、检查结果和候选内容；
- 全局任务坞：显示异步生成状态和需人工处理事项。

### 3. 结构化内容

- 小说/故事：大纲、卷、章、场景、人物和时间线；
- 剧本：场次、地点、时间、人物、动作、对白、音效和转场；
- 分镜：镜头号、景别、机位、运镜、画面、对白、音效、时长和提示词；
- 提示词：主体、场景、服装、道具、姿势、风格、镜头、负面词和模型参数；
- 广告文案：产品、受众、平台、语气、字数、标题、卖点和行动引导。

结构化内容同时保留纯文本编辑和导出能力，避免用户被固定表单限制。

### 5. 可调布局和侧栏状态

文本工作区两侧栏都支持手动调整：

- 左侧项目/章节栏与中央编辑器之间提供可拖拽分隔线；
- 右侧 AI/素材栏与中央编辑器之间提供可拖拽分隔线；
- 分隔线显示抓取提示和拖动反馈；
- 双击分隔线恢复默认宽度；
- 两侧均支持收起为窄图标栏，再次点击或拖动后展开；
- 窄窗口下优先收起侧栏，不压缩正文到不可编辑状态；
- 当前页面的侧栏宽度和收起状态按租户/项目保存，不能混用不同租户的数据。

建议边界：左栏最小 220px、默认 270px、最大 420px；右栏最小 320px、默认 460px、最大 620px。正文区始终保留可用的最小编辑宽度。

### 6. 文本素材库与素材中心的关系

文本素材库不是新的素材存储，也不复制素材文件；它是素材中心在文本创作工作区中的专用视图。素材的创建、上传、文件保存、项目归属、删除、回收站、租户隔离和基础元数据仍由素材中心统一负责。

右侧 AI 协作区增加“文本素材库”视图，按当前文档和项目筛选显示：

- AI 生成的候选段落、摘要、分析结果和版本片段；
- 本地上传的 `.txt`、`.md`、`.json`、`.csv` 等文本资料；
- 项目已有文本素材和历史版本；
- 用户标记的文献参考、摘录和来源信息。

每条素材继续使用素材中心的 `assetId` 和项目归属，并在文本视图中展示来源类型、原始文件名、创建时间、引用次数和来源链接/备注。素材只按当前项目显示，跨项目引用必须拒绝。

文本工作区不得直接写入素材文件目录，也不得维护第二份素材数据库。AI 生成的文本片段如果需要保存为素材，必须通过现有素材中心导入/创建接口完成，并回填正式 `assetId`。

### 7. 素材进入正文和 AI 上下文

素材卡片提供以下操作：

- 拖入正文：插入到光标位置或正文中的拖放区域；
- 复制：只复制正文内容，不丢失来源信息；
- 提取词句：从长文中选择句子、段落或关键词后形成新素材；
- 引用到 AI：只把用户选择的素材片段加入本次 AI 上下文；
- 查看原文：打开原始文档或来源记录；
- 保存为版本：把候选片段保存为当前文档的新版本。

这些操作只改变文本会话的引用关系或创建新的正式素材，不改变素材中心的统一归属规则。素材中心中的名称、项目、删除状态和文件可用性发生变化后，文本素材库应刷新并同步显示。

拖入正文前显示插入预览，用户确认后才写入正文。引用到 AI 时不默认注入整篇文献，避免上下文过大、无关内容混入和未经确认的事实传播。

编辑器应提供明显的“拖入正文以插入”区域，并支持从素材卡片拖到指定段落。无法拖放时，复制、粘贴和“插入正文”按钮必须提供等价操作。

### 4. AI围绕选中内容工作

支持续写、扩写、缩写、润色、改写、改变语气、增强冲突、转剧本、转分镜、转提示词、提取人物、提取场景和提取道具。

AI输出先进入候选区或差异预览，用户确认后才替换、插入或创建新版本，不能直接覆盖正文。

## 五、实施批次

### 批次 A：文本工作区稳定性

- 完善自动保存状态和失败重试提示；
- 增加未保存内容恢复；
- 明确自动版本、用户版本和AI版本；
- 保证切换会话、刷新页面和应用重启后内容不丢失；
- 保持现有项目和租户隔离。

### 批次 B：创作模式和模板

- 建立九类现有类型的模板元数据；
- 增加故事、小说、剧本、分镜、提示词、广告文案专用字段；
- 模板只影响编辑和AI提示，不改变现有文本数据兼容性；
- 老会话没有模板时按现有 `type` 平滑迁移。

### 批次 C：文本生成和结果回传

- 文本任务继续调用 `generation.create()`；
- 保留 `creationType: "text"`、原 `conversationId`、`projectId` 和来源上下文；
- 完成结果回填当前文本会话；
- 结果生成新版本或候选内容，不覆盖用户正在编辑的正文；
- 失败、验证码、登录失效、`submission_unknown` 和额度等待在原会话显示状态卡；
- 结果恢复只恢复/下载，不重新生成；
- 使用 `taskId` 和版本标识去重，防止重复回填。

### 批次 D：专业创作能力

- 章节树和场景树；
- 人物卡、人物关系和世界观资料；
- 分镜结构化视图；
- 提示词变量和模板；
- 多候选结果和版本分支；
- 文本转分镜、分镜转提示词。

### 批次 E：检查和导出

- 人物、时间线、场景和道具连续性检查；
- 错别字、格式和段落检查；
- 广告敏感词和表达风险检查；
- TXT、Markdown、JSON、剧本格式和分镜表导出；
- 导出内容不携带 API Key、Cookie、账号 Profile 或服务地址。

## 六、必须保持的功能红线

1. 不改变豆包账号队列、人工验证、`submission_unknown` 和额度锁行为；
2. 不改变无限画布的节点、DAG、输入证据和结果回填行为；
3. 不绕过统一 `generation.create()`；
4. 不新增文本专用调度器；
5. 文本任务仍和项目、会话、素材、任务一对一绑定；
6. 结果事件幂等，重复事件不能重复创建版本；
7. 结果恢复不得重新生成；
8. 跨项目素材引用必须拒绝；
9. 老版本文本会话可以继续打开、编辑、恢复和导出；
10. 任何共享模块回归失败都不得合并。

## 七、测试门禁

每个批次至少通过：

1. `test-text-workspace.cjs`；
2. 文本专用静态和结构化测试；
3. 版本安全、自动保存和租户隔离测试；
4. 文本结果回传和重复事件测试；
5. `test-text-workspace-responsive-runtime.cjs`；
6. 文本回归集合；
7. `npm test`；
8. 首页、任务坞、素材中心、无限画布、豆包管理和模型网关回归；
9. 隔离 `userData` 预览启动；
10. 文本真实交互验收：新建、输入、保存、生成、失败、恢复、版本恢复和导出。

当前环境缺少 Playwright 或 Electron/CDP 能力时，只能标记为环境阻塞，不能把静态通过等同于完整 UI 验收。

## 八、合并和回滚

支线只有在文本专用门禁、主线回归和隔离预览全部通过后才允许合并。

如出现以下情况，立即停止合并：

- AI结果覆盖正文；
- 同一任务产生重复版本；
- 结果回填到错误会话或错误项目；
- 旧会话无法打开或恢复；
- 文本改动影响豆包、画布、任务坞或模型网关；
- `submission_unknown` 被自动重提；
- 真实 UI 测试未完成却准备发布。

回滚优先使用 feature flag 和支线快照，不删除用户的文本、版本、任务或素材数据。
