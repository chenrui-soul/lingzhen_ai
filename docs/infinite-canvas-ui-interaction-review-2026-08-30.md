# 无限画布视觉与交互问题复核

日期：2026-08-30  
来源：用户最新截图与当前无限画布源码复核  
范围：仅无限画布模块，不修改其它模块

## 一、总体判断

这次截图暴露的不是单个按钮问题，而是“首屏创作、画布操作、资源管理、节点编辑”四套入口还没有形成清晰分工。

当前最需要调整的方向：

1. 顶部只保留画布级操作，不再放对单个节点没有明确作用的执行通道。
2. 空白画布拖动默认用于平移，不能因为普通拖动就框选全部节点。
3. 节点拖动只负责移动节点；只有拖动开始前已经打开节点编辑器，拖动结束后才恢复编辑器。
4. 首屏创作台必须把创作类型、参考素材、模型/账号、比例/时长和生成按钮一次性展示出来。
5. 项目资产选择应在画布内完成“选择并添加”，不能把用户直接跳转到资源库后丢失当前创作上下文。
6. 资源的“引用管理”和“项目资产 CRUD”要区分，避免误删项目原始素材。

## 二、截图中确认的视觉问题

### UI-01：顶部执行通道区域占位但作用不明确

截图中顶部持续显示“执行通道、账号分组、豆包账号”。这些参数并不直接决定当前画布上所有节点的执行方式：节点可能分别使用模型网关、豆包、不同账号、不同比例和时长。

结论：顶部全局执行通道会制造错误心智，且在窗口缩放后占据大量横向空间，挤压画布和工具栏。

调整方案：

- 从顶部命令栏移除执行通道、账号分组、豆包账号三个常驻控件。
- 顶部只保留：画布名称、保存状态、撤销/重做、适应画布、主题、导入/导出、沉浸模式、运行全部。
- 节点具体执行通道和参数只放在节点编辑器/右侧属性面板。
- 首屏创作台保留一套独立的生成配置，不与已进入画布后的节点配置混用。
- 若“运行全部”需要统一策略，改成点击运行全部时弹出的“本次运行配置”，而不是长期占据顶部。

### UI-02：顶部工具栏放大后被遮挡或压缩

截图显示在不同窗口尺寸和系统缩放下，顶部命令栏、左侧资源栏、右侧检查器之间有覆盖关系；工具按钮只剩图标，部分内容难以识别。

调整方案：

- 工具栏分为三层：画布名称区、画布动作区、运行区；不允许控件横向无限挤压。
- 动作区使用固定宽度图标按钮，文字只在宽屏显示。
- 工具栏增加 `overflow-x:auto` 或断点折叠菜单，但不能让按钮被其它层覆盖。
- 右侧检查器采用独立浮层，打开时覆盖画布，不改变顶部工具栏布局。
- 在 1280、1440、1920 宽度和 100%、125%、150% 系统缩放下分别验收。
- 任何面板都不能覆盖工具栏可点击区域；通过 z-index 和 pointer-events 明确分层。

### UI-03：首屏创作台截图仍表现为旧版简化界面

截图中首屏只有提示词输入、快捷创作卡片和少量按钮，没有稳定显示参考素材、模型/账号、比例/时长和生成按钮。当前源码虽然已经包含 `renderCreatorControls()`、项目资产选择和生成参数，但截图与源码预期不一致。

结论：这是必须优先验证的“源码已改但运行界面未生效/被遮挡/加载了旧状态”问题，不能只看静态代码通过。

调整方案：

- 首屏固定结构必须是：
  - 创作类型：文本 / 图片 / 视频
  - 主提示词输入
  - 参考素材：本地上传、从当前项目选择、已选素材列表、角色标记、移除
  - 生成配置：模型网关或豆包、账号、模型、比例、时长、分辨率等
  - 主按钮：生成并进入新无限画布
- 控件必须在首屏首屏可见，不放到快捷卡片之后，也不能依赖滚动才能发现。
- 加入运行时版本标记，例如 `data-lfc-ui-version`，用于确认客户端加载的是最新画布 UI。
- 首屏只在空画布显示；已有节点的画布不再显示首屏创作台。
- 点击生成后立即锁定按钮，创建新画布并自动进入新画布的节点流程。

### UI-04：项目资产选择入口行为不统一

当前源码已有“从项目资产选择”的选择器，但截图显示用户容易进入左侧“项目资产”列表，而不是完成“选择并添加”。这两种行为的语义不同：前者是资源浏览，后者是创作输入绑定。

调整方案：

- 首屏、节点编辑器、资源面板分别使用明确文案：
  - 首屏：`从项目选择参考素材`
  - 节点编辑器：`添加到当前节点`
  - 资源面板：`浏览项目资产`
- 选择器内点击素材只改变选中状态，点击“添加到创作台/添加到节点”后才提交。
- 不再因为点击选择按钮直接跳出当前创作界面。
- 选择器显示当前项目名称、素材类型过滤、已选数量和添加结果。
- 关闭选择器后保留已选状态，不清空用户刚才的勾选。

### UI-05：素材只有引用，没有完整的自定义管理

截图和源码都表明目前主要能力是上传、选择、拖入画布、移除引用。缺少素材别名、角色、标签、排序和安全删除等管理能力。

调整方案分两层：

#### 画布内安全编辑

- 可编辑画布内显示名称/别名。
- 可编辑角色：人物、场景、道具、动作、风格、首帧、尾帧、其它。
- 可调整参考素材顺序。
- 可从当前节点或创作台移除引用，但不删除项目原始素材。
- 可查看素材所属项目、类型、尺寸、时长和来源。

#### 项目资产操作

- 重命名、标签编辑、软删除、恢复必须明确标记为“项目资产操作”。
- 删除前显示影响范围：哪些节点正在引用、哪些任务使用过。
- 默认只做软删除，不直接物理删除文件。
- 如果底层资源 API 尚未提供安全更新/恢复能力，画布内先只提供“打开项目资源库”，不能伪造删除成功。

## 三、画布拖动和编辑器规则重新定义

### Interaction-01：空白区域拖动不应默认全选

当前代码在选择工具下，空白区域左键拖动会创建框选矩形；当矩形覆盖全部节点时，用户看到的就是“拖一下全选”。这属于当前交互定义与用户预期不一致，不是单纯视觉问题。

建议采用以下规则：

| 操作 | 结果 |
|---|---|
| 点击空白区域 | 取消选中，不移动画布 |
| 在空白区域左键拖动 | 平移画布，不框选、不全选 |
| 按住 Shift/Alt 再在空白区域拖动 | 框选节点 |
| 中键拖动 | 始终平移画布 |
| 按住 Space + 左键拖动 | 临时平移画布 |
| 拖动节点标题栏 | 只移动节点 |
| 拖动分组标题栏 | 移动分组及其成员 |
| 从输出端拖动 | 创建连线，不启动画布平移 |

这样可以把最常用的“看画布、移动画布”设为默认，把框选变成有意触发的动作，避免误选。

### Interaction-02：节点编辑器恢复规则需要保留拖动前状态

用户要求的准确规则是：

- 拖动开始时编辑器已经打开：拖动过程中隐藏，拖动结束后恢复编辑器。
- 拖动开始时编辑器没有打开：拖动过程中不显示，拖动结束后仍然不打开。
- 拖动节点后只恢复拖动前的选区、检查器折叠状态、编辑器状态和当前检查器 Tab。
- 不能因为“拖动结束”自动打开节点编辑器。
- 如果拖动的是非可编辑节点，也不能强行打开空编辑器。

当前实现中 `restoreEditorAfterDrag(..., openDraggedNode=true)` 会在节点拖动结束后主动打开被拖动节点的编辑器，这与最新要求冲突，需要改为根据拖动开始前的 `composerNodeId/composerFocused` 恢复。

### Interaction-03：拖动中隐藏编辑器不能遮挡画布，也不能改变布局宽度

拖动开始时应只隐藏编辑器内容和点击层，不重新计算画布主区域宽度；拖动结束后恢复原位置，避免画布跳动。

验收点：

- 开始拖动后 1 帧内编辑器不可见且不拦截鼠标。
- 画布 viewport 的 left、top、width 不因隐藏检查器而突然变化。
- 释放后节点位置、连线、分组边界立即同步。
- 取消拖动后恢复原坐标、历史栈和编辑器状态。

## 四、重复入口和按钮减负

### Entry-01：删除重复的“进入无限画布/隐藏画布”按钮

截图中至少有三个容易混淆的控制：

- 顶部沉浸模式按钮。
- 右侧检查器收起/展开按钮。
- 外层应用可能提供的右栏显示/隐藏按钮。

它们的视觉都像“进入/隐藏画布”，用户很难判断作用。

建议：

- 画布只保留一个“沉浸模式”按钮，放在顶部命令栏，使用明确 Tooltip：`进入沉浸模式/退出沉浸模式`。
- 右侧只保留一个检查器收起/展开按钮，Tooltip 改为`收起节点检查器/展开节点检查器`，不要使用“进入画布”含义。
- 在无限画布页面隐藏或禁用外层重复的右栏切换按钮。
- 左侧资源栏收起按钮只控制资源栏，不与沉浸模式共用图标。

## 五、切换其它模块再返回时闪烁

### Flash-01：模块切换会重新创建整个应用根节点

当前应用切换页面时会重建根节点，返回无限画布后会经历“空壳/加载/重新渲染”的过程，所以用户看到闪一下是可以解释的。

在不修改其它模块的前提下，先做无限画布内部优化：

1. 保留当前画布运行时快照和最近一次已渲染 DOM 所需数据。
2. 返回画布时先同步渲染上次状态，不显示全屏 loading 卡片。
3. 后台刷新项目、任务、模型和素材数据，完成后只做局部更新。
4. 只有首次进入、项目切换或数据确实失效时才显示加载态。
5. 返回画布时不自动重新 `fitView`，避免视口和节点再跳一次。
6. 取消无限画布首屏的入场动画和不必要的 opacity transition。

如果仍需做到完全无闪，需要改变外层页面切换策略；该动作可能涉及 `app.js`，不应在未授权前扩大范围。

## 六、首屏和画布的最终界面分工

### 首屏创作台

- 只负责：输入灵感、选参考素材、选模型/账号/参数、点击生成。
- 生成后一定新建画布。
- 不显示画布节点库、运行现场、历史版本和复杂工具栏。
- 不显示与当前创作无关的全局执行通道。

### 进入画布后

- 只负责：节点编排、输入绑定、模型参数、运行、结果预览、素材引用和任务追踪。
- 顶部不再重复首屏的整套生成配置。
- 节点编辑器只有用户主动打开或拖动前已经打开时才显示。
- 画布空白拖动默认平移，框选使用明确修饰键。

## 七、建议实施顺序

### 第 1 批：马上修复

1. 移除顶部常驻执行通道区域。
2. 修正节点拖动结束后错误自动打开编辑器的问题。
3. 重新定义空白区域拖动：默认平移，修饰键框选。
4. 只保留一个沉浸模式入口，隐藏重复的外层按钮。
5. 为首屏增加 UI 版本标记并做真实截图确认，解决“源码已改、界面仍旧版”的问题。

### 第 2 批：资源和首屏闭环

1. 统一首屏/节点/资源面板的素材选择语义。
2. 支持画布内素材别名、角色、标签、排序和移除引用。
3. 补齐媒体错误态、重试和导入结果明细。
4. 确保参考图片、视频、音频作为独立素材引用，文本素材提取正文后作为文字传递。

### 第 3 批：稳定性和视觉验收

1. 返回画布优先恢复快照，后台刷新，减少闪烁。
2. 完成 1280/1440/1920 宽度和系统缩放验收。
3. 完成工具栏、检查器、资源抽屉的遮挡和点击命中验收。
4. 重写 G5 真实鼠标夹具，确认平移、框选、打组和节点拖动。
5. 补齐弹层 Escape、遮罩关闭、焦点恢复和键盘导航。
