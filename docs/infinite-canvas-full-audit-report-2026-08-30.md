# 无限画布完整审计报告

审计日期：2026-08-30  
审计范围：仅限无限画布模块及其专属测试、样式和画布数据适配逻辑。  
本轮性质：只审计、不修改功能、不提交真实生成任务。

## 1. 结论摘要

当前无限画布已经完成阶段零至七的大部分基础优化，核心自动化能力没有发现回归：新版 Electron G6 运行验收 18/18，通过的静态专项测试共 18 组，覆盖节点拖动、滚轮缩放、媒体比例、输入快照、结果恢复、历史兼容、沉浸式布局和范围隔离。

但“测试通过”不等于真实交互已经闭环。本次补查发现：

- 3 项代码级交互缺口需要优先处理：取消任务后的轮询与错误提示、首屏重复提交、删除/撤销运行中节点的任务保护。
- 2 项弹窗和输入体验缺口会直接影响操作顺畅度：新建画布弹窗不能通过 Escape 或遮罩关闭，长文本编辑主要依赖失焦保存。
- 媒体失败态、素材文本读取失败、批量导入部分失败等异常路径提示不足。
- 旧版 G5 真实鼠标验收在当前 Electron 页面仍有 3/7 失败，虽然新版 G6 18/18 通过，但平移、框选和打组不能在重新做真实 UI 验证前视为完全收口。
- Playwright 视觉验收仍未执行，低分辨率、系统缩放、真实面板遮挡、媒体比例和拖动隐藏的最终效果尚未获得截图证据。

建议优先级：先修复 P1，再校准 G5/补齐真实 UI 验收，之后处理 P2 异常态和 P3 细节。

## 2. 已确认问题

### IC-A01：取消任务后仍会继续等待一次轮询，并产生错误提示

- 优先级：P1
- 位置：`desktop/src/renderer/infinite-canvas.js:820-829`、`:1128-1131`、`:1134`
- 复现条件：从无限画布右侧运行面板取消一个正在运行的任务。
- 当前表现：取消函数先提示“已取消/已停止追踪”，但执行该任务的 `awaitTask()` 没有取消信号，仍会等待约 1.2 秒再次请求任务状态；读到 `cancelled` 后抛出异常，`runSingleNode()` 又会显示错误 Toast。用户可能同时看到成功提示和错误提示。
- 影响：误导用户以为取消失败；增加无意义的 bootstrap 请求；运行态视觉可能短暂回跳。
- 建议：为每个任务增加取消令牌或 `runtime.cancelledTaskIds`；取消成功后立即让 `awaitTask()` 返回 `{cancelled:true}`，由调用层显示一次明确结果；禁止把用户主动取消显示为错误。
- 是否改代码：是。
- 是否影响其它模块：不应影响其它模块，只修改无限画布的任务等待和状态收口。

### IC-A02：首屏生成没有异步提交锁，快速双击可能创建多个画布和任务

- 优先级：P1
- 位置：`desktop/src/renderer/infinite-canvas.js:503-519`、`:566`
- 复现条件：在“灵感，即刻成帧”首屏输入内容后快速双击生成按钮，或连续按 Ctrl/Cmd+Enter。
- 当前表现：按钮只根据输入是否为空禁用，没有 `creatorSubmitting` 状态；表单提交会同步创建新画布并调用 `runSingleNode()`，快速重复提交可能在第一次任务状态写入前再次创建画布。
- 影响：重复画布、重复任务、重复扣费风险；用户难以判断哪一个画布是有效结果。
- 建议：提交开始立即锁定按钮和表单；按钮显示“正在创建画布…”；创建失败、任务提交失败或进入可追踪状态后统一解锁；为请求增加一次性提交 ID，前端在当前首屏会话内去重。
- 是否改代码：是。
- 是否影响其它模块：不影响。

### IC-A03：运行中节点可以被删除或被撤销移除，任务绑定没有保护

- 优先级：P1
- 位置：`desktop/src/renderer/infinite-canvas.js:121`、`:1006`
- 复现条件：节点处于生成中时使用 Delete 删除节点，或通过撤销恢复到任务提交前的画布版本。
- 当前表现：删除节点和恢复历史没有检查节点是否处于 `activeStates`；节点删除后任务仍可能在任务中心/豆包端继续执行，但画布上的 `taskNodeMap` 绑定会失效，结果无法回填原节点。
- 影响：生成结果丢失、计费与画布脱节、用户误以为任务已经被删除或取消。
- 建议：删除/撤销涉及运行中节点时弹出二次确认；明确提供“仅从画布移除，任务继续执行”或“先停止追踪再删除”；若允许删除，保留一个脱离画布的任务恢复入口，不能静默丢失结果。
- 是否改代码：是。
- 是否影响其它模块：只需修改无限画布操作保护；任务取消仍走已有统一接口。

### IC-A04：新建画布弹窗无法通过 Escape 或点击遮罩关闭

- 优先级：P2
- 位置：`desktop/src/renderer/infinite-canvas.js:1021`
- 复现条件：打开“新建空白画布”弹窗后按 Escape，或点击弹窗外的遮罩区域。
- 当前表现：新建画布使用 `<div class="lfc-modal-backdrop">`，但遮罩没有关闭绑定；全局 Escape 只处理拖动、预览和专注编辑，没有处理 `runtime.modal`。
- 影响：用户只能点击右上角或“取消”，与常规弹窗交互不一致；误打开后退出成本高。
- 建议：遮罩点击关闭，弹窗内部点击阻止冒泡；Escape 关闭当前最高优先级弹层；打开时记录触发按钮，关闭后恢复焦点。
- 是否改代码：是。
- 是否影响其它模块：不影响。

### IC-A05：文本素材读取失败被静默吞掉

- 优先级：P2
- 位置：`desktop/src/renderer/infinite-canvas.js:366`
- 复现条件：给文本输入节点选择文本素材，模拟 `api.assets.readText()` 失败或返回空内容。
- 当前表现：读取文本的 catch 为空；素材 ID 仍会写入节点引用，但文本正文不会进入输入框，也没有错误、重试或“仅保留素材引用”的说明。
- 影响：再次提交时用户以为文本已经导入，实际模型收到的 prompt 可能缺少关键内容，复现困难。
- 建议：逐项记录读取结果；失败素材显示“读取失败/重试”；如果继续保留引用，明确说明不会作为文字传入；成功后再写入文本草稿，并避免半成功状态覆盖旧内容。
- 是否改代码：是。
- 是否影响其它模块：不影响。

### IC-A06：图片、视频、音频资源缺少明确的加载失败态和重试入口

- 优先级：P2
- 位置：`desktop/src/renderer/infinite-canvas.js:293-299`、`:371`；媒体样式位于 `desktop/src/renderer/styles/canvas-media-v2.css`。
- 复现条件：素材 URL 过期、文件被移动、视频编码不支持或网络加载失败。
- 当前表现：媒体只设置 `src`，没有统一的 `error` 监听和错误占位；节点可能显示空白、黑框或一直停留在加载状态，预览窗口也没有重试按钮。
- 影响：用户无法区分“正在加载”“素材失效”“模型没有返回结果”；视频预览异常时容易误判为节点闪烁或生成失败。
- 建议：统一媒体状态模型：loading、ready、error、unsupported；错误态显示素材名、错误原因和“重试加载/重新绑定/打开项目资源库”；视频和音频预览保留控制栏，不因局部刷新重复创建媒体元素。
- 是否改代码：是。
- 是否影响其它模块：仅画布媒体展示。

### IC-A07：运行现场 Dock 与当前画布统计口径不一致

- 优先级：P2
- 位置：`desktop/src/renderer/infinite-canvas.js:628`、`:837`
- 复现条件：存在多个画布，至少两个画布都有无限画布任务；当前画布右侧显示的是 A 画布，底部运行现场同时展示 A、B 的任务。
- 当前表现：Dock 使用所有 `creationSource === "infinite-canvas-v2"` 的任务；无节点选中时的运行面板也会展示所有无限画布任务，但顶部统计和助手统计只计算当前画布节点。
- 影响：用户看到“运行中 1 个”但列表可能有其它画布任务；当前画布切换后容易误操作其它画布的任务。
- 建议：提供明确的“当前画布 / 全部画布”筛选；默认当前画布，列表中显示画布名；如果保留全局运行现场，顶部统计也明确标注全局，并增加画布筛选。
- 是否改代码：是，或需要先确认产品口径。
- 是否影响其它模块：不影响任务中心，只改画布展示口径。

### IC-A08：底部运行现场没有取消/停止追踪入口

- 优先级：P2
- 位置：`desktop/src/renderer/infinite-canvas.js:628`；右侧面板 `:841` 已有取消入口。

- 是否改代码：是。
- 是否影响其它模块：不影响。

### IC-A09：当前画布仍是固定 4000×2400 的大画布，不是完全可扩展的无限画布

- 优先级：P2
- 位置：`desktop/src/renderer/styles/infinite-canvas.css:8` 的 `.lfc-world`。
- 复现条件：持续向负方向或超过 4000×2400 范围拖动节点，或放大/缩小后使用小地图观察边界。
- 当前表现：世界层固定为 4000×2400，缩放范围固定为 12%–180%；小地图按固定比例计算，负坐标和超出固定范围的节点可能无法准确表达。
- 影响：与“无限画布”的产品心智不完全一致；大型流程继续扩展时会遇到小地图和适应画布边界问题。
- 建议：改为可扩展世界边界或按节点范围动态扩容；统一处理负坐标、边界扩容、小地图视口和 fitView；明确是否采用“无限逻辑坐标 + 可视区域按需扩展”。
- 是否改代码：是。
- 是否影响其它模块：不影响。

### IC-A10：长文本编辑保存策略不一致，Composer 主要依赖失焦

- 优先级：P2
- 位置：`desktop/src/renderer/infinite-canvas.js:350-359`。
- 复现条件：在节点专注编辑器中输入长文本后，未失焦就切换页面、关闭窗口或触发其它操作。
- 当前表现：节点内文本编辑器使用 `oninput` 持续更新；Composer 文本框使用 `onchange`，主要在失焦时保存。用户输入过程中如果应用被关闭或页面被切换，最新文本不一定已写入数据。
- 影响：文本创作内容丢失；同一种“输入框”在不同入口表现不一致。
- 建议：Composer 使用节流 `oninput` 保存草稿，失焦执行立即保存；显示保存状态；关闭编辑器前主动 flush；长文本输入只创建一次撤销快照。
- 是否改代码：是。
- 是否影响其它模块：不影响。

### IC-A11：弹层缺少统一焦点管理和无障碍语义

- 优先级：P3

- 建议：建立统一弹层生命周期：打开记录触发元素、聚焦首个可操作控件、Tab 限制在弹层、Escape 关闭最高层、关闭后恢复触发元素。
- 是否改代码：是。
- 是否影响其它模块：不影响。

### IC-A12：批量导入的部分成功、重复和不兼容文件反馈不完整

### IC-A13：生成结果预览仍缺少加载、失效和声音策略

## 3. 高风险待验证问题

### IC-R01：G5 真实鼠标验收仍有 3 项失败

- 优先级：P1
- 证据：`desktop/scripts/log/infinite-canvas-g5-runtime.json`。
- 当前结果：4/7 通过，失败项为“真实点击可切换到平移工具”“真实鼠标框选可选中多个节点”“工具栏可把框选节点打组”；测试随后因分组对象为空中断。
- 可能原因：旧 G5 夹具使用了当前沉浸式布局下不再稳定的坐标/事件假设，也不能排除真实按钮命中、选择层覆盖或 pointer capture 问题。
- 结论：不能直接判定为生产代码缺陷，也不能直接忽略。需要重新设计不依赖固定坐标的真实 UI 夹具，分别验证：按钮命中后 `tool-pan` 状态、空白框选的起止点、框选结果、打组按钮可用状态和分组拖动。
- 建议：把 G5 重写为基于 DOM bounding box 的点击和拖动；同时保留一条纯 CDP 真实鼠标路径，记录每一步命中元素和事件后状态。

### IC-R02：真实视觉验收暂未执行

- 优先级：P1
- 证据：`desktop/scripts/test-infinite-canvas-ui.cjs` 依赖 Playwright，但 `desktop/package.json` 未声明或安装 Playwright。
- 未覆盖内容：低分辨率、系统缩放、弹层遮挡、工具栏点击命中、编辑器贴合、媒体比例节点尺寸、拖动中隐藏编辑器的同帧效果、视频/音频实际预览。
- 建议：在独立测试环境补齐 Playwright 或使用现有 Electron CDP 建立截图验收；不应在本轮擅自扩大生产依赖。

### IC-R03：模型能力不完整时的参数显示需要真实验证

- 优先级：P2
- 静态代码已有能力过滤，但仍需实测：模型没有 ratios/durations 时是否隐藏对应控件；豆包视频比例/时长是否显示固定能力；不兼容素材是否在首屏、Composer 和节点属性栏中保持一致。
- 建议：准备“无能力模型、仅图片模型、仅视频模型、豆包模型”四套夹具，逐项检查首屏和节点编辑器。

### IC-R04：取消与实时状态存在竞态风险

- 优先级：P2
- 现状：取消操作、`onLiveStatus`、`syncCompletedTask` 和 `awaitTask` 都可能写入同一节点状态。
- 风险：取消后如果旧的 generating/submitting 状态事件晚到，节点可能短暂回到运行中；之后又被取消状态覆盖。当前静态测试没有覆盖“取消与迟到状态事件同时发生”。
- 建议：每个任务维护单调状态版本或取消时间戳；忽略取消之后到达的旧事件；增加竞态测试。
