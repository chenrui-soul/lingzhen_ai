# 无限画布 UI 与交互修订方案

日期：2026-08-30  
范围：仅限无限画布模块、无限画布专属样式和专属测试。  
本轮状态：已完成问题确认和方案整理，尚未修改功能代码。

## 1. 本轮结论

这次反馈包含 9 个相互关联的问题：

1. 顶部“执行通道 / 账号分组 / 豆包账号”占用画布级空间，但并不是所有节点的统一执行参数。
2. 顶部工具栏在窄窗口、系统缩放和左侧区域展开时会被压缩或遮挡。
3. 首屏“灵感，即刻成帧”虽然已有动态控件代码，但运行截图仍只显示旧版首屏，必须增加版本标记并完成真实界面确认。
4. 项目资产入口既像“浏览资源库”，又像“选择素材添加”，用户无法判断点击后是否会返回当前创作上下文。
5. 素材管理仍缺少画布内的别名、角色、标签、排序和移除引用等细节操作。
6. 切换其它模块再返回时会出现闪烁或重新布局，影响沉浸感。
7. “进入/隐藏无限画布”、右侧收起按钮、外层右栏按钮语义接近，入口重复。
8. 空白区域左键拖动在选择模式下会进入框选，容易出现全选节点后整张画布跟随拖动的错觉。
9. 节点拖动结束后会强制打开节点编辑器，不符合“按拖动前状态恢复”的要求。

其中第 8、9 项是已从代码中确认的交互缺陷，不是截图误判。

## 2. 必须保持的产品边界

- 只修改无限画布模块。
- 不修改登录、租户、管理中心、任务中心、豆包管理、模型网关和其它业务页面。
- 不改变已有任务提交接口和账号配置逻辑，只调整无限画布内部的展示、绑定和状态管理。
- 不删除已有项目素材；画布中“移除”只解除引用，项目资产删除必须单独确认。
- 不恢复短剧生产流程作为默认入口；历史短剧画布只保留兼容读取能力。

### 2.1 统一术语

为避免“项目资产”同时表示三种不同范围，后续界面和代码统一使用：

| 统一名称 | 含义 |
|---|---|
| 创作项目 | 用户看到的一张独立无限画布 |
| 当前画布资产 | 当前创作项目自己的素材清单 |
| 其它创作项目 | 同一无限画布模块中的其它画布 |
| 共享项目资产 | 后台真实工作台项目中的资源库 |
| 后台项目 | 任务、会话和原始资产真正绑定的 `projectId` |

界面不再使用含义模糊的“项目资产”单独作为标签。左侧标签改为“当前画布资产”，跨项目入口明确写成“从其它项目选择”，后台资源入口明确写成“共享项目资产”。

## 3. 交互规则定稿

### 3.1 顶部命令栏

顶部只保留画布级动作：

- 画布名称和保存状态；
- 撤销、重做；
- 适应画布；
- 主题；
- 导入、导出；
- 唯一的沉浸模式切换；
- 运行全部。

移除顶部常驻的执行通道、账号分组和豆包账号控件。节点执行通道和参数只出现在节点编辑器；运行全部如需统一策略，点击后再打开本次运行配置弹层。

### 3.2 面板职责

只保留三种明确职责：

| 区域 | 唯一职责 | 不能承担的职责 |
|---|---|---|
| 左侧资源栏 | 节点库、画布元素、当前画布资产和跨项目资源入口 | 不作为沉浸模式开关 |
| 中央画布 | 节点编排、连线、媒体预览 | 不被弹层永久挤窄 |
| 右侧检查器 | 当前节点属性、输入、参数、运行状态 | 不作为“进入画布”入口 |

右侧检查器收起按钮文案改为“收起节点检查器 / 展开节点检查器”；沉浸模式只由顶部一个按钮控制。无限画布页面隐藏外层重复的右栏按钮。

### 3.3 空白画布拖动、框选和节点拖动

| 用户操作 | 结果 |
|---|---|
| 点击空白 | 取消选择，不移动画布 |
| 空白区域左键拖动 | 默认平移画布，不框选 |
| Shift/Alt + 空白区域左键拖动 | 框选节点 |
| 中键拖动 | 平移画布 |
| Space + 左键拖动 | 临时平移画布 |
| 节点标题栏拖动 | 只移动节点 |
| 节点输出端拖动 | 创建连线 |
| 画布工具栏“选择” | 只决定节点点击、选中和修饰键框选，不再让普通空白拖动框选 |

拖动状态恢复规则：

- 开始拖动前编辑器已打开：拖动中隐藏编辑器，拖动结束恢复原编辑器、当前节点、Tab 和折叠状态。
- 开始拖动前编辑器未打开：拖动中隐藏编辑器，拖动结束仍保持关闭。
- 拖动结束不得因为被拖动节点可编辑而主动打开编辑器。
- 拖动未达到阈值时视为点击，保留原点击选择行为。
- 隐藏编辑器只改变可见性和点击层，不重新计算中央画布宽度，避免拖动时画布跳动。

代码实施时需要移除节点拖动结束调用中的强制打开参数，并以拖动开始时记录的 `composerNodeId`、`composerFocused`、`inspectorCollapsed` 和 `inspectorTab` 为唯一恢复依据。

## 4. 首屏创作台修订

### 4.1 固定首屏结构

首屏必须在同一个可滚动创作卡片内显示：

1. 标题：`灵感，即刻成帧`；
2. 创作类型：文本、图片、视频；
3. 主创意输入框；
4. 参考素材：本地上传、从当前画布选择、从其它项目选择、拖入、已选列表、角色和移除；
5. 模型/账号和生成参数；
6. 主按钮：`生成并进入无限画布`。

快捷卡片只作为“新建节点骨架”的辅助入口，不能遮住或替代上述配置，也不能伪装成平台已经内置的模型预设。

### 4.1.1 快捷入口不再使用预设逻辑

平台当前没有正式的内置预设配置中心，因此“故事脚本、角色设定、场景参考、图片生成、视频生成”不能再执行以下行为：

- 不切换首屏创作类型；
- 不自动填入提示词；
- 不自动选择模型网关、豆包账号、模型、比例或时长；
- 不写死“4 秒女主跳舞”等示例内容；
- 不自动提交生成任务；
- 不创建短剧生产流程专用节点；
- 不向当前已有画布继续追加一组节点。

点击快捷入口后，统一执行：

```text
新建独立画布
    ↓
创建对应的空节点骨架
    ↓
建立必要连线
    ↓
进入新画布并适应视图
    ↓
等待用户填写内容、选择素材和配置模型
```

节点只保存通用类型和空配置，不保存所谓的“预设 ID”。后期平台具备正式预设中心后，再通过独立版本字段接入，不能让当前临时节点结构冒充正式预设。

### 4.1.2 五个快捷入口的节点骨架

| 快捷入口 | 新画布节点 | 默认连线 | 自动执行 |
|---|---|---|---|
| 故事脚本 | 文本输入、文本生成 | 文本输入 → 文本生成 | 否 |
| 角色设定 | 文本输入、人物参考、图片生成 | 文本输入 → 图片生成；人物参考 → 图片生成 | 否 |
| 场景参考 | 文本输入、场景参考、图片生成 | 文本输入 → 图片生成；场景参考 → 图片生成 | 否 |
| 图片生成 | 文本输入、图片生成 | 文本输入 → 图片生成 | 否 |
| 视频生成 | 文本输入、图片参考、视频参考、音频参考、视频生成 | 各输入节点 → 视频生成 | 否 |

具体规则：

#### 故事脚本

- 创建普通“文本输入”节点；
- 创建通用“文本生成”节点；
- 不创建故事大纲、分集剧本、编剧 Agent 等短剧专用节点；
- 文本生成节点的模型和参数为空，等待用户打开编辑器配置。

#### 角色设定

- 创建普通“文本输入”节点；
- 创建一个空的“人物参考”图片输入节点，角色固定为人物；
- 创建“图片生成”节点；
- 人物参考节点没有素材时显示“添加人物参考”，不能放示例图片；
- 不创建角色设定 Agent 或其它内容处理节点。

#### 场景参考

- 创建普通“文本输入”节点；
- 创建一个空的“场景参考”图片输入节点，角色固定为场景；
- 创建“图片生成”节点；
- 场景参考节点没有素材时显示“添加场景参考”；
- 不创建场景设定 Agent 或短剧专用节点。

#### 图片生成

- 创建普通“文本输入”节点和“图片生成”节点；
- 用户后续自行从节点库添加人物、场景、道具、动作或风格参考；
- 不自动创建无实际内容的多个参考节点，保持画布简洁。

#### 视频生成

- 创建普通“文本输入”节点；
- 创建图片参考、视频参考和音频参考三个空输入节点；
- 创建“视频生成”节点并连接上述输入；
- 不写死豆包账号、Seedance 模型、4 秒、比例或提示词；
- 用户打开视频生成节点编辑器后，再选择豆包/模型网关、模型、账号、比例和时长；
- 如果后续认为三个空媒体节点过多，可通过用户测试改成“文本输入 + 视频生成”，其它参考节点由用户按需添加，但本轮先按完整媒体入口实现。

### 4.1.3 快捷入口与画布状态

- 每次点击快捷入口都创建新的独立画布，不复用当前画布；
- 新画布使用 11 节定义的独立 `assetScope`；
- 节点初始状态统一为 `idle`，没有任务 ID、结果或运行历史；
- 创建后选中文本输入节点，但不自动打开节点编辑器；
- 只有用户主动点击节点编辑按钮，才打开编辑器；
- 自动执行一次 `fitView`，随后不得再因为数据刷新跳动视口；
- 新建失败时保持原画布不变，并显示一次错误提示；
- 快速重复点击使用新建锁，不能一次创建多个画布。

### 4.1.4 首屏快捷入口与右侧快捷入口统一

首屏快捷卡片和右侧“快速补充流程”目前行为不同，必须统一：

- 首屏快捷入口：新建独立画布并创建对应节点骨架；
- 右侧检查器不再显示“快速补充流程”五个按钮，避免误以为会向当前画布应用预设；
- 当前画布需要新增节点时，统一从左侧节点库拖入，或在画布空白处右键创建；
- 如未来恢复“追加节点组合”，必须单独命名为“插入节点组合”，不能复用首屏快捷入口名称。

### 4.2 首屏真实版本确认

当前源码已有 `renderCreatorControls()`，但截图没有显示完整控件。因此实施前先加入：

- `data-lfc-ui-version="creator-v2"`；
- 页面右下角仅测试环境可见的版本诊断信息，生产视觉不显示；
- 首屏渲染日志：首次挂载、控件渲染、当前创作类型、模型数据状态；
- 确认客户端加载的是当前源码页面，不是旧打包页面或旧进程窗口。

同时删除 `renderCreatorStudio()` 中重复的 `updateCreatorPromptState()` 调用。

### 4.3 生成行为

- 点击生成立即锁定按钮和表单，按钮显示“正在创建画布…”；
- 当前创作台输入只用于新建画布，不复用旧画布；
- 新建成功后立即进入新无限画布；
- 提示词、参考图片/视频/音频、模型和参数回传为节点数据；
- 生成任务失败时恢复首屏按钮，并保留用户输入和素材选择；
- 防止双击或 Ctrl/Cmd+Enter 重复创建画布和重复扣费。

## 5. 当前画布资产和共享资产管理

### 5.1 “浏览”与“选择添加”分开

- 左侧“当前画布资产”：浏览、筛选、搜索和拖入当前画布；
- 首屏“从当前画布选择”：在弹层中多选后点击“添加到创作台”；
- 首屏“从其它项目选择”：选择其它创作项目或共享项目资产；
- 节点编辑器“从当前画布选择”：在弹层中多选后点击“添加到当前节点”；
- 节点编辑器“从其它项目选择”：选择后引用或复制到当前画布，再添加到节点；
- 点击选择按钮不能直接跳离当前创作页面。

弹层必须显示当前创作项目名、来源项目名、类型过滤、已选择数量、素材缩略图、已选状态和添加结果。

### 5.2 画布引用编辑

画布内可对引用进行：

- 修改显示别名；
- 设置角色：人物、场景、道具、动作、风格、首帧、尾帧、其它；
- 添加和编辑标签；
- 调整参考素材顺序；
- 从当前节点移除引用；
- 查看来源项目、文件类型、尺寸、时长和导入时间。

“移除引用”不删除项目资产。

### 5.3 后台项目原始资产删除边界

只有进入“共享项目资产”管理上下文后才能执行原始资产重命名、软删除和恢复。删除前显示引用影响：

- 被哪些画布节点引用；
- 是否被历史任务使用；
- 删除后当前节点是否保留失效引用。

如果底层资源接口不支持安全更新/恢复，本轮不伪造共享资产删除成功，先完成当前画布引用管理和明确提示。

## 6. 工具栏和沉浸式布局

### 6.1 防遮挡布局

- 顶部命令栏分为标题区、动作区、运行区；
- 删除顶部执行通道后，动作区不再被三组下拉框挤压；
- 宽屏显示文字和图标，窄屏只显示图标并保留 Tooltip；
- 工具栏使用 `min-width:0`、明确的 `flex-shrink` 和断点折叠菜单；
- 不允许检查器、资源栏或弹层覆盖顶部可点击区域；
- 右侧检查器打开时使用独立浮层，不改变顶部栏坐标；
- 预览弹层和创作台弹层层级高于画布、低于系统窗口控制区域。

### 6.2 沉浸模式

- 默认进入无限画布时使用沉浸式布局；
- 顶部只保留一个进入/退出沉浸模式按钮；
- 资源栏和检查器可独立收起，不再复用沉浸模式图标；
- 不能同时出现两个含义接近的“隐藏画布/进入画布”按钮；
- 画布 viewport 在切换面板时保持当前缩放和视口，不自动跳回原位。

### 6.3 小窗口和系统缩放验收

至少验收：

- 1280 × 720，100%；
- 1440 × 900，125%；
- 1920 × 1080，100%；
- 窄宽度下左侧资源栏收起、右侧检查器浮层和创作台滚动。

## 7. 返回画布闪烁处理

在不修改外层业务页面逻辑的前提下，先在无限画布内部处理：

1. 保存当前画布快照、视口和面板状态；
2. 返回画布先恢复最近一次已渲染状态；
3. 后台刷新项目、任务、模型和素材；
4. 数据刷新只做局部更新，不显示全屏 loading；
5. 返回时不重复 `fitView`；
6. 取消画布入场 opacity/transform 动画；
7. 首次进入或数据失效时才显示加载态。

如果仍然闪烁，说明外层 `app.js` 正在重建整个根节点。届时必须单独确认是否授权修改外层页面切换策略，本方案不默认扩大范围。

## 8. 需要一并补齐的细节问题

这些问题不是本次截图的主诉，但会直接影响优化后的体验，应纳入同一轮专项验收：

- 新建画布弹窗支持遮罩点击关闭和 Escape 关闭；
- 所有资源选择、素材预览和属性弹层统一焦点恢复；
- 图片、视频、音频加载失败显示错误态和重试按钮；
- 视频预览默认静音，避免打开预览突然播放声音；
- 文本素材读取失败不能静默吞掉，需逐项显示失败原因；
- 批量导入显示成功、重复、不兼容、读取失败明细；
- 运行中节点删除、撤销和批量操作需要保护，不能静默丢失结果绑定；
- 提交前停止任务后结束本地等待，不再同时出现“已停止”和“任务失败”；提交确认后的任务继续等待并正常回填；
- 底部运行现场与右侧运行面板统一“当前画布 / 全部画布”统计口径；
- Composer 长文本使用节流输入保存，关闭前主动 flush；
- 画布世界范围、负坐标、小地图和 fitView 继续验证固定 4000×2400 是否足够。

## 9. 分批执行步骤

### 第 1 批：立即修正核心交互

1. 移除顶部常驻执行通道区域；
2. 合并重复沉浸/隐藏入口；
3. 空白左键拖动默认平移，Shift/Alt 框选；
4. 修正节点拖动后编辑器按原状态恢复；
5. 增加首屏 UI 版本标记并用真实客户端截图验证；
6. 增加首屏提交锁。

### 第 2 批：资源闭环

## 11. 画布与资产库的独立项目模型

### 11.1 产品定义

你的判断是正确的：用户在无限画布中点击“新建”，应当理解为开始一个新的独立创作项目，而不是在原画布上继续堆叠内容。

每个画布需要拥有独立的：

- 画布节点、连线、分组和视口；
- 当前画布素材清单；
- 当前画布生成结果；
- 当前画布的提示词、模型参数和运行记录入口；
- 素材别名、角色、标签和排序；
- 素材引用关系和删除/移除状态。

不同画布之间默认不可见、不可互相修改。切换画布后，左侧“当前画布资产”只显示目标画布的资产，不再显示所有画布共用的素材集合。

### 11.2 不建议直接把后台项目切换成画布 ID

当前代码中的 `runtime.projectId` 是工作台级项目 ID，生成任务、文本会话、模型资源和资产接口都使用它做归属校验。不能简单地在切换画布时把 `runtime.projectId` 改成画布 ID，否则可能造成：

- 已有任务被误判为其它项目任务；
- 生成结果无法回填；
- 资源接口因不存在对应后台项目而上传失败；
- 登录后的当前项目状态被无限画布覆盖；
- 其它业务页面看到错误的当前项目。

因此采用两层模型：

| 层级 | 含义 | 默认范围 |
|---|---|---|
| 工作台项目 | 后台已有的真实项目，负责账号、任务和基础资源归属 | 可被无限画布使用，但不因切换画布而改变 |
| 无限画布创作项目 | 画布内部的独立创作空间 | 每个画布独立 |

第一阶段只在无限画布内部实现创作项目隔离，不修改后台项目切换和其它页面。

### 11.3 当前画布资产范围

每个画布增加独立的资产清单，例如：

```js
canvas.assetScope = {
  version: 1,
  localAssetIds: [],
  importedAssetIds: [],
  generatedAssetIds: [],
  references: {},
  updatedAt: ""
}
```

资产分类规则：

- `localAssetIds`：当前画布直接上传并纳入画布的素材；
- `importedAssetIds`：从其它画布或共享项目资产引入的素材；
- `generatedAssetIds`：当前画布生成的图片、视频、音频或文本结果；
- `references`：素材在当前画布中的别名、角色、标签、排序和来源信息。

所有生成结果默认加入当前画布的 `generatedAssetIds`。同一个后台资源可以被多个画布引用，但每个画布的引用信息独立保存，修改别名、角色和标签不会影响其它画布。

### 11.4 左侧资产库显示规则

左侧标签统一改为“当前画布资产”，只显示当前画布资产视图：

1. 默认只显示当前画布的 `localAssetIds`、`importedAssetIds` 和 `generatedAssetIds`；
2. 切换画布时先切换资产清单，再刷新节点引用；
3. 画布标题旁显示当前资产数量，例如“当前创作项目 · 8 个素材”；
4. 素材卡片显示来源标签：本地上传、当前画布生成、来自其它画布、共享项目；
5. 画布内移除只从当前画布清单移除，不删除后台原始资源；
6. 如果当前画布引用了已失效或被软删除的资源，显示“素材已失效”，不能静默消失。

切换画布的顺序必须是：

```text
保存当前画布状态
    ↓
切换 activeCanvasId
    ↓
恢复目标画布的节点、资产清单和视口
    ↓
刷新当前画布资产面板
    ↓
后台同步共享项目资源和任务状态
```

不能先显示旧画布资产，再短暂显示全部项目资产，最后才切到目标资产，否则会出现用户看到的“资源闪烁”和误操作。

### 11.5 从其它项目选择添加素材

需要增加一个独立入口：`从其它创作项目选择`。它与`当前画布资产`分开，不能混在同一个列表中。

选择器分为三层：

- 当前创作项目：当前画布已拥有的素材；
- 其它创作项目：用户有权限访问的其它画布素材；
- 共享项目资源：后台项目中可复用的原始素材。

用户在其它项目选择素材后，必须明确选择一种操作：

| 操作 | 结果 |
|---|---|
| 引用到当前画布 | 当前画布保存引用关系，源素材只读，不复制文件 |
| 复制到当前画布 | 创建当前画布自己的资产清单记录，后续别名和标签独立 |
| 仅预览 | 不改变当前画布 |

默认推荐“复制到当前画布”，因为它更符合独立项目的心智，也能避免源项目删除或改名后影响当前创作。若底层接口暂时不支持文件复制，则第一阶段使用只读引用，并在素材卡上明确显示“来自项目 X”。

### 11.6 跨项目素材权限和安全边界

- 只能选择当前租户和用户有权限访问的项目；
- 不允许通过手工修改素材 ID 绕过项目权限；
- 跨项目选择器默认只读，不能在当前画布内直接修改源项目素材；
- 删除当前画布引用不删除源项目素材；
- 源项目素材被删除、失效或权限变化时，当前画布显示失效状态并提供重新绑定；
- 工作流导入时按“当前画布资产 / 跨项目资产 / 缺失资产”分别报告，不静默替换。

### 11.7 与生成任务的绑定

每个生成任务继续绑定真实后台 `projectId`，同时增加无限画布 `canvasId` 和资产清单版本：

```js
executionEnvelope: {
  projectId,
  canvasId,
  assetScopeVersion,
  assetIds,
  referenceAssets
}
```

结果回填必须同时校验：

- 后台项目一致；
- 画布仍然存在；
- 节点仍然存在；
- 资产清单版本没有被错误覆盖；
- 当前任务属于该画布的生成会话。

切换画布不能改变已提交任务的状态，也不能把任务结果回填到当前选中的其它画布。

### 11.8 执行顺序

1. 为每个画布补充 `assetScope`，对旧画布按当前已有节点引用自动迁移；
2. 将左侧“当前画布资产”改为当前画布资产过滤；
3. 切换画布时同步恢复目标画布资产和视口；
4. 首屏和节点编辑器的“从项目选择”默认指向当前画布；
5. 增加“从其它创作项目选择”只读选择器；
6. 实现引用/复制的明确反馈；
7. 生成结果自动加入当前画布资产清单；
8. 增加跨画布切换、跨项目选择、源素材失效和结果回填测试。

### 11.9 本需求的最终判断

从产品体验上，应当让用户感觉“新建画布就是新项目”，各画布资产完全独立；同时保留一个明确的“从其它项目选择素材”入口。

从技术实现上，第一阶段采用“后台项目不切换 + 无限画布内部创作项目隔离”的方式最安全。等资源服务具备正式的跨项目复制和权限接口后，再考虑把画布创作项目映射为后台真实项目，不应在本轮直接改动全局 `projectId`。

## 12. P1/P2 问题的实施级补充规范

本节把现有方案中分散的异常处理要求合并成可直接开发和验收的规则，避免同一个问题在多个章节重复实现，或只写了“需要处理”但没有定义成功、失败和竞态行为。

### 12.1 提交边界：从“取消任务”改为“提交前停止”

大模型任务一旦被远端平台确认接收，就不能暂停、撤回或取消。无限画布必须以“远端是否确认接收”为唯一分界，不能把本地停止轮询误称为取消生成。

任务增加明确的提交阶段：

| 提交阶段 | 例子 | 是否允许用户停止 | 停止后的结果 |
|---|---|---|---|
| `preparing/uploading/configuring` | 尚未向平台确认提交 | 可以停止本地流程 | 不创建远端任务，可重新提交 |
| `submitting` | 正在提交，是否已接收尚未确认 | 仅适配器确认未提交时允许停止 | 返回“提交前已停止” |
| `submitted/generating/running` | 平台已确认接收 | 不允许暂停或取消 | 继续等待，结果正常回填 |
| `downloading/verifying` | 已生成，正在下载或校验 | 不允许暂停 | 继续完成结果回填 |
| `submission_unknown` | 无法确认平台是否收到 | 不自动重提 | 等待人工核对 |
| `failed` 且未提交 | 提交前失败 | 可以修正后重新提交 | 清理临时状态后重试 |

任务控制对象应记录远端确认边界，而不是笼统的 `cancelled`：

```js
runtime.taskControl.set(taskId, {
  submissionPhase: "preparing",
  remoteAccepted: false,
  stopRequested: false,
  statusVersion: 1
})
```

执行规则：

1. 本地适配器只有在确认平台已接收任务后才设置 `remoteAccepted=true`；
2. `remoteAccepted=true` 后隐藏“取消任务”“暂停”“停止追踪”按钮，显示“已提交，无法暂停”；
3. 提交前点击“停止”时设置 `stopRequested=true`，让本地等待流程返回 `{stoppedBeforeSubmit:true}`；
4. 提交前停止不能进入错误 Toast，也不能把节点标记为模型生成失败；
5. 提交前失败允许重新运行，必须清理旧的临时提交状态；
6. `submission_unknown` 不得自动重提，也不能直接标记为已取消；
7. 任务一旦已提交，即使用户切换画布、关闭检查器或离开无限画布，也继续监听并正常回填原画布；
8. 只有提交前明确停止成功时才忽略后续本地状态；已提交任务的 completed 事件必须接收；
9. `runSingleNode()`、`awaitTask()`、`syncCompletedTask()` 和实时状态回调共用提交阶段收口函数；
10. 任务进入 completed、failed 或人工核对终态后清理控制对象。

实现注意：不能仅根据 `generating`、`running`、`submitting` 等状态名称猜测提交边界。应由豆包适配器返回明确字段，例如 `remoteAccepted`、`submissionConfirmedAt` 或等价信息。如果 `api.generation.create()` 返回的任务 ID 已代表豆包平台接收成功，则从该返回点开始任务不可停止；只有本地准备、素材上传、页面填写或提交失败且未被平台接收时才允许停止或重试。

正确规则是：

```text
提交前停止 → 结束本地流程，允许重新提交
提交后不可停止 → 继续监听，completed 正常回填原画布
提交状态未知 → 不自动重提，等待人工核对
```

验收：

- 在素材上传或参数配置阶段点击停止：本地流程结束，可重新提交；
- 在豆包已经返回任务 ID 后：界面没有暂停或取消按钮；
- 提交后切换到其它画布：原任务继续运行，完成结果回填原画布；
- 提交后收到迟到 completed：正常回填，不被误判为取消；
- 提交前失败：显示失败原因并允许重试；
- `submission_unknown`：显示“待核对”，不自动再次生成。

### 12.2 首屏生成防重复提交

首屏生成需要同时设置 UI 锁和请求幂等标识，不能只依赖按钮 disabled：

```js
runtime.creatorSubmitting = {
  requestId: "creator-...",
  startedAt: 0,
  canvasId: "",
  phase: "idle"
}
```

提交阶段：

1. 表单提交的第一行检查 `phase !== "idle"`，已提交时直接忽略；
2. 立即锁定主按钮、创作类型、素材选择和参数控件；
3. 先创建新画布，再把 `requestId` 写入画布草稿；
4. 只允许该 `requestId` 触发一次节点生成；
5. 成功进入可追踪状态后，按钮保持锁定并显示“已进入画布”；
6. 创建画布失败、节点提交失败或校验失败时解锁，并保留所有输入；
7. 页面切换或重复触发不能再创建第二个画布；
8. 最终 toast 只允许出现一次成功或失败结果。

Ctrl/Cmd+Enter、鼠标双击、触摸快速点击和辅助卡片触发生成必须共用同一个提交函数，不能各自调用 `startCreatorGeneration()`。

### 12.3 已提交节点删除、撤销和跨画布切换保护

已提交的生成不能暂停，所以删除节点也不能被解释为取消生成。删除操作只处理“画布引用”和“结果回填目标”，不能改变远端任务状态。

删除、撤销、重做、批量删除和删除其输入连线前，先查找节点关联的任务提交阶段：

- 提交前任务：允许停止本地流程后再删除；
- 已提交任务：弹出确认，提示“任务已经提交，删除节点不会停止生成”；
- 提交状态未知：禁止静默删除，提示先完成人工核对。

用户确认删除已提交节点后：

1. 节点标记 `detachedFromCanvas: true`；
2. 保存 `{taskId, canvasId, nodeId, detachedAt}` 的结果归属记录；
3. 远端任务继续执行，不能调用不存在或不支持的取消接口；
4. 任务完成后不写入已删除节点，但将结果放入“结果待认领”；
5. 运行现场提供“恢复为素材节点”或“恢复原节点”操作；
6. 恢复节点时重新建立任务映射，不重复提交任务。

历史操作规则：

- 如果撤销会删除运行中节点，先弹确认；
- 如果撤销只改变位置、参数或连线，不影响任务绑定，可以直接执行；
- 重做、粘贴和复制运行中节点时不能复制旧的活动任务 ID；
- 删除节点后，任务不能因为 `findTaskBinding()` 找不到节点而被静默丢弃；已提交任务仍需保留结果记录。

### 12.4 弹层统一关闭和焦点规则

当前画布存在新建画布、主题、素材选择、素材预览、创作台素材选择和节点编辑器等多个弹层，必须统一为“弹层栈”，不能每个弹层单独处理 Escape。

规则：

1. 每个弹层有唯一层级和 `role="dialog" aria-modal="true"`；
2. 打开时保存触发按钮，聚焦弹层第一个可操作控件；
3. Escape 只关闭最上层弹层；
4. 点击遮罩关闭，点击弹层内容不冒泡；
5. 关闭后恢复触发按钮焦点；
6. 弹层打开期间 Tab 不跳到下面的画布和外层页面；
7. 运行中的任务确认弹层不能被普通 Escape 误关闭；
8. 未保存的长文本弹层关闭前先执行 flush；
9. 关闭素材选择弹层时保留已选草稿，只有点击取消才回滚本次临时选择。

重点修复：新建画布弹层当前只有按钮关闭，必须补遮罩和 Escape；主题弹层、素材选择弹层和预览弹层也必须复用同一套关闭生命周期。

### 12.5 媒体加载状态、重试与防闪烁

图片、视频和音频素材统一使用四态：

```text
loading → ready
        ↘ error
        ↘ unsupported
```

每个媒体节点保存展示状态，不因局部任务刷新而重复创建媒体元素：

- `loading`：显示骨架和素材名称；
- `ready`：显示媒体，可点击放大；
- `error`：显示失败原因、重新加载、重新绑定；
- `unsupported`：显示编码或格式不支持，并提供替换素材。

重试规则：

1. 优先复用相同元素重新设置 `src`，不整张重建节点；
2. 重试前清除旧错误状态；
3. 失败 3 次后显示“检查项目资产”入口；
4. 预览窗口和节点内预览共用状态，但互不自动播放；
5. 视频和音频默认静音或不自动播放；
6. 节点尺寸比例来自素材元数据，加载失败时保留上次合法尺寸；
7. 结果刷新不得让视频元素从头闪烁或重新播放。

### 12.6 文本素材读取结果不能静默丢失

文本素材添加到节点时必须拆分为“素材引用”和“正文导入”两个结果：

| 结果 | 节点表现 |
|---|---|
| 读取成功 | 保存素材引用，并把正文作为文字写入输入草稿 |
| 返回空内容 | 保留引用，显示“素材为空” |
| 读取失败 | 保留引用，显示“读取失败 / 重试” |
| 格式不支持 | 不写入输入框，显示“不支持的文本格式” |

不能因为读取失败仍把素材 ID 写入后就假装导入成功。重新读取成功后才更新输入草稿，不能覆盖用户已经手动修改的文字。

文本传递验收：

- 豆包输入框接收的是正文字符串，不是 `.txt` 文件对象；
- 图片、视频、音频仍然作为独立媒体输入；
- 多个文本素材按用户排序拼接，并保留素材标题分隔；
- 用户手动修改后的文本不会被重新读取覆盖；
- 读取失败有可定位的素材名称和重试按钮。

### 12.7 运行现场的统计和任务范围

运行现场必须明确提供范围筛选：

- `当前画布`：只显示 `canvasId === runtime.activeId` 的任务；
- `全部画布`：显示当前无限画布模块创建的所有任务，并显示画布名；
- 默认使用`当前画布`，避免误操作其它画布任务。

所有统计必须使用同一个过滤函数，不能让顶部统计、右侧面板和底部 Dock 各自过滤：

```js
getCanvasTasks({ scope: "current" | "all", nodeId, includeTerminal })
```

每条任务必须显示：画布名、节点名、任务状态、进度、执行通道、创建时间和结果归属。

切换画布后：

1. 当前画布统计立即切换；
2. 后台任务仍继续执行；
3. 任务状态回调按 `canvasId` 更新原画布；
4. 当前画布看不到其它画布的任务，除非切换到“全部画布”；
5. 任务结果不能因当前画布变化而改变归属。

### 12.8 底部运行 Dock 的提交前停止和结果操作

底部 Dock 与右侧运行面板必须提供一致的任务动作：

- 提交前任务：`停止提交`；
- 已提交任务：不显示取消、暂停或停止追踪按钮，显示`已提交，无法暂停`；
- 已失败任务：`重新运行`；
- 已完成任务：`查看结果`；
- 结果待认领任务：`恢复为素材节点`；
- 其它画布任务：`定位到画布`，不能直接改变当前节点选择。

点击 Dock 中的“停止提交”按钮：

1. 只锁定当前任务条；
2. 不重建整张画布；
3. 只允许处理 `remoteAccepted=false` 的任务；
4. 复用 12.1 的提交阶段控制对象；
5. 更新该任务条和对应节点状态；
6. 如果当前任务属于其它画布，显示画布名并保持当前画布不切换；
7. 已提交任务点击状态区域时只定位节点或打开结果，不触发停止；
8. 提交前主动停止不显示为错误。

因此，当前如果 `canvasTaskCanStop(task)` 对所有活动中的豆包任务都返回可停止，需要改为只对 `remoteAccepted=false` 且提交阶段属于本地准备阶段的任务返回可停止；已返回远端任务 ID 的豆包任务必须返回不可停止。

## 14. 资产库自定义编辑、删除与恢复规范

### 14.1 先区分三种操作对象

资产相关操作不能全部叫“编辑素材”或“删除素材”，必须明确操作对象：

| 操作对象 | 保存位置 | 影响范围 | 默认操作 |
|---|---|---|---|
| 当前画布引用 | `canvas.assetScope.references` | 只影响当前画布 | 直接编辑 |
| 当前画布素材清单 | `canvas.assetScope.localAssetIds/importedAssetIds/generatedAssetIds` | 只影响当前画布可见性 | 可移除、可恢复 |
| 后台项目原始资产 | 资源库资产记录 | 可能影响多个画布和任务 | 需要确认后软删除 |

必须避免以下误操作：

- 在节点中点击“移除素材”时删除后台原始文件；
- 在当前画布删除共享素材时影响其它画布；
- 修改当前画布别名时改变源项目的原始名称；
- 在素材选择弹层中误触发全局删除；
- 任务正在使用素材时直接物理删除文件。

### 14.2 支持的自定义编辑内容

#### 当前画布级编辑

当前画布可以直接编辑，不需要修改后台原始资产：

- 显示别名；
- 当前画布角色：人物、场景、道具、动作、风格、首帧、尾帧、其它；
- 当前画布标签；
- 当前画布排序；
- 作为哪个节点的参考素材；
- 移除当前画布引用；
- 恢复刚刚移除的引用。

这些数据保存到 `assetScope.references[assetId]`，不覆盖资产库原始名称和原始标签。

#### 原始资产级编辑

在“项目资产”管理视图中支持：

- 原始资产名称；
- 资产描述；
- 项目级标签；
- 软删除；
- 从回收站恢复。

文件类型、文件路径、媒体内容和资产 ID 不允许在普通编辑表单中修改。替换文件必须使用独立的“重新上传版本”操作，并保留旧版本引用关系。

### 14.3 资产卡片操作布局

每个资产卡片统一提供：

- 点击缩略图：预览；
- 点击卡片主体：选择素材；
- 拖动卡片：复制或引用到画布；
- `＋`：添加到当前画布；
- `⋯`：打开资产操作菜单。

操作菜单：

- 编辑资产信息；
- 编辑当前画布标签和角色；
- 查看被哪些画布引用；
- 移除当前画布；
- 删除项目资产；
- 查看回收站记录。

“删除项目资产”不能出现在首屏选择器和节点输入选择器中，避免创作过程中误删原始素材。

### 14.4 删除规则

#### 删除当前画布引用

只从当前画布的资产清单和引用表中移除：

1. 不调用后台删除接口；
2. 不删除文件；
3. 不影响其它画布；
4. 不影响已经提交的生成任务；
5. 可以通过撤销或“恢复引用”找回。

#### 删除项目原始资产

项目资产删除必须采用软删除：

1. 删除前查询引用关系；
2. 显示当前画布、其它画布和历史任务的影响；
3. 如果有已提交任务正在使用，提示“删除不会停止任务，但可能影响结果下载或后续重新运行”；
4. 用户确认后写入 `deletedAt`、`deletedBy`、`deleteReason` 和资产版本号；
5. 从正常资产列表隐藏，进入回收站；
6. 所有引用位置保留失效记录，不静默移除节点中的资产 ID；
7. 预览和生成前显示“素材已删除”，提供重新绑定；
8. 恢复时重新出现在原项目资产库，不自动改变画布中的别名和角色。

项目资产删除不能物理删除文件，除非未来增加单独的“永久删除”权限和二次确认流程。本轮不实现永久删除。

### 14.5 正在运行任务和结果资产的保护

删除前必须检查：

- 是否被提交前任务引用；
- 是否被已提交任务引用；
- 是否是某个节点当前输出；
- 是否是历史结果；
- 是否被其它画布复制或引用。

处理规则：

- 提交前任务：可以停止本地流程，再删除当前画布引用；
- 已提交任务：不能通过删除素材来停止任务，任务继续执行；
- 当前输出素材：删除前提示结果会从当前画布预览中消失，但任务记录仍保留；
- 其它画布正在使用：允许当前项目解除引用，但全局删除必须额外确认；
- 结果资产下载中：禁止物理替换，允许软删除并保留任务结果恢复入口。

### 14.6 删除、编辑的并发与失败回滚

资产编辑不能只依赖前端乐观更新，需要保存资产版本或 `updatedAt`：

```js
assetMutation = {
  assetId,
  operation: "update" | "soft-delete" | "restore",
  baseVersion,
  requestId,
  scope: "canvas-reference" | "project-asset"
}
```

规则：

1. 同一资产连续点击保存只提交最后一次有效变更；
2. 删除和恢复请求使用幂等 `requestId`；
3. 后台返回版本冲突时不覆盖用户最新编辑，提示“资产已被其它位置修改，请刷新后确认”；
4. 网络失败时恢复原卡片状态，显示重试按钮；
5. 软删除成功后如果局部刷新失败，保留删除状态并提供刷新，不显示假成功；
6. 恢复失败时不把资产错误地显示为可用；
7. 批量操作逐项记录成功、失败、冲突和跳过原因。

### 14.7 资产接口不支持时的降级

如果现有资源 API 暂不支持重命名、标签更新、软删除或恢复：

- 仍然实现当前画布级别的别名、角色、标签、排序和移除引用；
- 原始资产编辑按钮显示“当前资源服务暂不支持”；
- 不把本地改名伪装成后台改名成功；
- 不直接删除本地文件；
- 提供复制资产到当前画布作为替代方案；
- 把接口缺口记录到专项验收报告，不阻塞其它无限画布交互优化。

### 14.8 旧数据迁移

已有画布没有 `assetScope` 时，首次加载执行一次只读迁移：

1. 扫描所有节点的 `refs.assetIds`、输出资产和历史结果；
2. 去重生成当前画布的资产清单；
3. 根据节点角色、素材类型和来源补齐 `references`；
4. 记录 `assetScope.migratedFromVersion`；
5. 保存成功后不重复迁移；
6. 迁移失败保留原节点引用，并显示“资产范围待修复”，不能清空原引用。

旧画布的资产默认归入当前画布，不自动把其它画布的共享素材复制过来。跨项目资产只有在用户明确选择后才加入目标画布。

### 14.9 资产编辑实施顺序

1. 建立当前画布资产过滤和 `assetScope` 读取辅助函数；
2. 先实现画布级别的别名、角色、标签、排序和移除引用；
3. 增加资产卡片操作菜单和预览/选择事件隔离；
4. 增加引用关系查看和失效状态；
5. 对接后台资产名称、描述和标签更新接口；
6. 对接软删除和恢复接口；
7. 增加版本冲突、失败回滚和幂等请求；
8. 增加回收站视图和恢复操作；
9. 完成跨画布、跨项目和运行任务保护验收；
10. 最后再评估永久删除，不纳入当前交付。

## 16. 删除整个创作项目（画布）的规则

既然用户把每张画布理解为一个独立创作项目，删除画布就不能只删除节点数据，还必须处理当前画布资产和已提交任务的归属。

### 16.1 删除前检查

点击删除画布后先显示确认页，至少列出：

- 画布名称；
- 节点数量和生成结果数量；
- 当前画布独有资产数量；
- 来自其它项目的引用数量；
- 尚未完成的提交前任务数量；
- 已提交但仍在生成的任务数量；
- 是否存在待认领结果。

### 16.2 删除处理

- 提交前任务：允许停止本地流程后删除；
- 已提交任务：继续在后台执行，不能因为删除画布而伪造取消；
- 已提交任务的结果：保留到任务中心和结果待认领记录；
- 当前画布独有资产：从当前画布资产清单移除；原始后台资产默认保留，只有用户在共享资产管理中明确确认后才软删除，不能因删除画布自动删除；
- 来自其它项目的引用：只解除当前画布引用，不影响源项目；
- 共享项目资产：只解除当前画布引用，不删除源资产；
- 删除后的画布：进入无限画布回收站，支持恢复；
- 恢复画布时恢复节点、连线、资产清单、引用和未完成任务绑定，不重复提交任务。

### 16.3 删除后任务回填

任务完成时按以下顺序处理：

1. 查找原 `canvasId`；
2. 画布存在且节点存在：正常回填原节点；
3. 画布存在但节点已删除：进入结果待认领；
4. 画布已回收：进入该画布的待恢复任务列表；
5. 画布永久清理未实现前：任务结果不能直接丢弃。

这条规则必须和 12.1 的“已提交后继续执行”保持一致，不能因用户删除画布而误触发任务取消。

### 16.4 删除整个画布的验收

- [ ] 删除有已提交视频任务的画布，不调用远端取消；
- [ ] 任务完成后结果仍能在任务中心或待认领区找到；
- [ ] 删除只引用其它项目素材的画布，不影响源项目素材；
- [ ] 删除当前画布独有素材，不物理删除原始文件；
- [ ] 恢复画布后节点和资产引用完整；
- [ ] 删除确认弹窗明确显示任务和资产影响范围；
- [ ] 删除操作支持撤销或回收站恢复；
- [ ] 没有活动任务时也不会误删其它画布。
