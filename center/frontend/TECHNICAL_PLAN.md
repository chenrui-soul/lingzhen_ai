# lingzhen_center 前端技术方案

## 1. 项目定位

`lingzhen_center` 前端是灵帧唯一的 Web 管理中心和用户账号服务入口，面向普通用户的本人账户页面，以及租户管理员、运营人员和平台管理员的后台页面。桌面端用户只负责使用，所有租户、成员、角色、公共模型目录、平台 Skill、审计和系统管理操作都必须在本管理中心完成。管理中心不承担桌面端的视频创作功能，也不提供密钥管理页面。

### 首期范围

- 用户自助注册、登录、退出、找回密码和会话续期
- 无邀请码创建个人租户；使用邀请码加入目标租户
- 仪表盘：用户、租户、在线设备、异常登录、积分和服务状态
- 用户、租户、Membership、邀请、系统角色和权限管理
- 设备、登录会话和强制下线
- 用户积分钱包、充值套餐、充值订单和积分流水
- 模型厂商、模型发现、能力参数、价格、租户启停和目录发布
- 仅平台后台管理员可用的 Skill 上传、扫描结果、版本发布、模型绑定、能力声明，以及租户启停和执行审计
- 公告管理
- 审计日志查询
- 旧认证退场和客户端升级状态查看，仅展示迁移状态，不恢复密钥权限

### 暂不纳入

- 桌面端视频生成操作
- 豆包 Cookie、Chrome Profile 管理
- 图片、视频等大文件在线存储
- 无限画布和创作工作区

## 2. 推荐技术栈

| 层级       | 首选技术                     | 用途                                       |
| ---------- | ---------------------------- | ------------------------------------------ |
| 运行环境   | Node.js 24 LTS + pnpm        | 本地开发和构建                             |
| 框架       | Vue 3 + TypeScript           | 管理后台页面与组件                         |
| 构建工具   | Vite                         | 开发服务器、构建和环境变量                 |
| 路由       | Vue Router                   | 登录态和权限路由                           |
| UI 组件    | Ant Design Vue               | 表格、表单、弹窗、分页和后台布局           |
| 客户端状态 | Pinia                        | 当前用户、界面偏好和少量跨页面状态         |
| 服务端状态 | TanStack Vue Query           | 请求缓存、失效刷新、并发请求和重试         |
| API 类型   | OpenAPI + openapi-typescript | 从后端接口文档生成类型，避免前后端字段漂移 |
| 图表       | Apache ECharts               | 仪表盘趋势和统计图                         |
| 单元测试   | Vitest + Vue Testing Library | 组件与业务逻辑测试                         |
| E2E        | Playwright                   | 注册登录、租户成员、设备、权限和异常路径   |
| 代码质量   | ESLint + Prettier + vue-tsc  | 规范、格式和类型检查                       |

## 3. 选型对比

| 方案         | 优势                                               | 代价                                              | 结论 |
| ------------ | -------------------------------------------------- | ------------------------------------------------- | ---- |
| Vue 3 + Vite | 学习成本较低，中文后台生态成熟，适合表单和数据管理 | 与当前原生 Electron 不能直接共享 UI 组件          | 首选 |
| React + Vite | 生态最大，复杂交互能力强                           | 状态和组件选型更分散，首期后台项目收益不明显      | 备选 |
| Next.js      | SSR、全栈路由和 SEO 完整                           | 本项目无 SEO 需求，引入服务端渲染会增加部署复杂度 | 不选 |

接受的代价：前端不会直接复用桌面端原生 JavaScript 页面，只共享 API 类型、业务枚举和设计 Token。若未来团队全面转向 React，可在管理中心模块扩大前重新评估。

```text

├─ api/                    # OpenAPI 生成类型、请求客户端
├─ layouts/                # 登录布局、管理后台布局
├─ router/                 # 路由表、登录和权限守卫
├─ stores/                 # 当前用户与界面状态
├─ features/
│  ├─ auth/
│  ├─ dashboard/
│  ├─ users/
│  ├─ tenants/
│  ├─ memberships/
│  ├─ invitations/
│  ├─ access-control/
│  ├─ devices/
│  ├─ sessions/
│  ├─ credits/
│  ├─ recharge/
│  ├─ models/
│  ├─ skills/
│  ├─ announcements/
│  └─ audit/
```

依赖方向保持为：`app → features → api/components/utils`。功能模块之间不得直接读取对方内部 Store，跨模块数据通过 API 或明确的公共接口传递。

## 5. 登录与安全设计

- Web 登录凭据使用 `HttpOnly + Secure + SameSite` Cookie，禁止把访问令牌存入 `localStorage`。
- 状态变更请求携带 CSRF Token。
- 前端路由守卫只负责用户体验，最终权限必须由后端校验。
- 管理中心登录必须创建 `client_type=management_web` 的 Session；桌面端 Session 不得复用为管理中心 Session。
- 登录过期时先尝试一次无感续期；续期失败再返回登录页。
- 注册成功后，无邀请码用户进入新建的个人租户；有邀请码用户进入目标租户，前端不自行拼装 Membership。
- 多租户登录时展示后端返回的可选租户并消费一次性租户选择票据，不能在前端伪造 `tenant_id`。
- 不在错误弹窗、监控日志或浏览器控制台输出密码、Token、数据库地址和签名密钥。
- 管理员执行停用用户、暂停租户、移除成员、调整高权限角色或强制下线等高风险操作时要求二次确认，并显示影响对象。
- 前端不能直接确认充值成功或修改用户余额，只能展示后端订单状态和追加式流水。
- 模型凭据输入后不回显明文；页面只显示是否已配置和脱敏标识。
- Skill 上传与发布页面只对平台后台管理员开放；租户管理员只显示启停和参数配置，不显示上传、替换或发布入口。
- 浏览器只负责上传到后端签发的受控地址并展示扫描结果，不在前端解包、执行或信任 Skill 内容。
- 用户自行导入本地 Skill 属于桌面端功能，不经过管理中心前端，也不写入平台 Skill 目录。
- 文件写入、终端、浏览器和外部网络能力必须使用醒目的风险标签；前端不能代替桌面端完成本机操作审批。

## 6. API 与状态管理

- 统一使用 `/api/v1`。
- 本地联调时 Vite 代理固定指向 `http://127.0.0.1:9001`；不得自动探测其他后端端口。
- 后端生成 OpenAPI 文档，前端自动生成 TypeScript 类型。
- TanStack Query 管理列表、详情和统计数据；Pinia 不复制服务端数据。
- 写操作成功后按资源键失效缓存，不进行全站强制刷新。
- 列表默认使用游标分页；筛选条件同步到 URL，便于刷新和分享。
- 所有请求附带 `X-Request-Id`，便于前后端排查同一请求。

## 7. UI 与交互原则

- 默认桌面管理后台最小适配宽度 1280px，同时保证 1024px 下可用。
- 信息密度以清晰为优先，表格行高、字号和按钮热区不做过度压缩。
- 危险操作统一使用红色语义，不依赖颜色作为唯一提示。
- 加载、空数据、权限不足、网络错误、会话过期必须有独立状态。
- 页面级弹窗同一时间只允许一个主模态框，避免重复遮挡。
- 所有表单字段有可见标签和明确错误信息。

## 8. 测试方案

首期自动化至少覆盖：

1. 正确登录、错误密码、账号禁用和会话过期。
2. 不同角色访问同一页面的允许与拒绝路径。
3. owner/admin/platform_admin 的桌面端 Token 访问管理中心 API 时返回 403；重新通过管理中心登录后才按角色开放页面。
4. 无邀请码注册创建个人租户；有效邀请码注册加入目标租户；重复账号和无效邀请码不留下半成品数据。
5. 强制设备下线后，旧会话不能继续访问。
6. 列表分页、筛选、刷新和乱序响应。
7. 网络中断、接口 401/403/409/429/500 的界面反馈。
8. 页面中不得出现密码、Refresh Token 或数据库连接串。
9. 支付渠道重复回调后，页面余额和流水只能增加一次。
10. 模型目录发布、停用、租户启停和余额不足状态均能正确展示。
11. 页面和浏览器日志中不得出现平台模型 API Key、完整上游 URL 或私有 Header。
12. Skill 新版本发布后旧版本只读，历史执行仍显示锁定版本和价格。
13. A 租户不能查看或启停 B 租户 Skill，直接构造请求由后端返回 403。
14. 高风险能力未声明、签名失败或审批过期时，页面必须显示明确状态且不能伪装为普通执行失败。
15. 普通用户和租户管理员不能看到上传/发布按钮，直接调用接口也必须由后端返回 403。
16. 上传路径穿越包、超大解压包或签名失败包时，版本保持不可发布并展示具体扫描项。
17. 成员被移除、角色被收回或租户被暂停后，旧路由和缓存不能继续执行对应操作。
18. 新客户端界面不出现密钥输入、激活、续期、冻结或密钥到期提示。

## 9. 构建与部署

- 开发环境使用 Vite 开发服务器；开发端口不作为生产连接契约。
- 新后端 API 端口固定为 `9001`；生产环境通过同域反向代理转发到该端口。
- 生产构建输出静态文件，由 Nginx 或后端同域托管。
- 前端和 API 使用同域部署，减少 CORS 与 Cookie 配置风险。
- 环境变量只允许包含公开 API 基础路径，不得包含数据库密码和签名密钥。
- 构建必须基于锁文件，CI 执行 `lint → typecheck → test → build → e2e`。

## 10. 实施顺序

1. 初始化 Vue/TypeScript/Vite 和代码质量工具。
2. 建立设计 Token、基础布局和登录页。
3. 接入 OpenAPI 类型与统一请求层。
4. 实现注册、用户、租户、Membership、邀请、角色权限、设备和会话页面。
5. 实现用户积分、充值套餐、充值订单和积分流水页面。
6. 实现模型厂商、模型能力、价格、租户启停和目录发布页面。
7. 实现 Skill 目录、版本、模型绑定、能力声明、租户启停和执行审计页面。
8. 实现公告、审计日志和仪表盘。
9. 补齐 Playwright E2E、安全检查和生产构建。

## 11. 验收标准

- `pnpm lint`、`pnpm typecheck`、`pnpm test` 和 `pnpm build` 全部通过。
- 用户从注册/登录到进入个人租户或受邀租户的核心路径可以完成。
- 租户管理员可以邀请成员、调整允许的角色并撤销会话；普通成员不能绕过后端权限进入管理页面。
- 桌面端 Session 不能直接打开或调用管理功能；管理操作必须通过管理中心 Session 完成。
- 401/403/409/429/500 和断网路径均有明确反馈。
- 浏览器存储中不存在密码和长期 Refresh Token。
- 前后端字段全部来自 OpenAPI 类型，不手写重复 DTO。
- 管理中心不包含密钥管理页面，新平台请求中不出现 `activate/verify` 认证调用。
- 用户可以查询余额、创建充值订单并看到幂等到账流水，但不能从前端直接改余额。
- 管理员可以维护并发布模型目录，桌面端能够获取可调用状态、能力参数和积分价格。
- 平台后台管理员可以上传并发布不可覆盖的平台 Skill 版本并配置模型、能力和租户范围；租户管理员和普通用户不能向后台上传 Skill。普通用户在桌面端导入的本地 Skill 不进入管理中心目录。
